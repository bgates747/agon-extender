The example defaults to V2. Its portrait timing dimensions differ from the
landscape product description: verify rotation and memory layout explicitly.
Derived from those totals, nominal scan rates are approximately 73.0 Hz (V1)
and 46.7 Hz (V2), not automatically 60 Hz. These are arithmetic estimates,
not measured panel rates. Olimex's older 100-fps demonstration is not an EDP
performance guarantee or a reason to overclock the delivered panel.

The example configures the P4 D-PHY supply through LDO channel 3 at 2.5 V;
that internal PHY supply is distinct from the panel connector supply. V1 uses
GPIO7/8 for I²C. Optional refresh instrumentation uses GPIO20: leave it disabled
until the actual Extender harness allocation has been checked. The README's
generic pin sketch includes two data lanes despite this panel using one;
use the actual board schematic and cable pinout, not that sketch alone.

## Scope and design boundaries

The P4 DSI peripheral drives the LCD through the board's DSI connector and FPC.
EMOS continues routing Agon VDU traffic to EDP over the existing UART path;
P4 EDP renders it and an output adapter presents the resulting pixels to DSI.
No new Agon application protocol or MOS bypass is required for initial output.

Keep upstream drawing, scrolling, clipping, sprites and palette semantics.
If DSI needs contiguous RGB565/RGB888 scanout buffers, those are output buffers,
not grounds to replace the inherited rendering storage. Document conversion,
rotation, lifetime, cache/DMA coherency and presentation ownership explicitly.
Do not hold renderer/UART locks while waiting for a display frame. Preserve
USB keyboard, recovery, SD service and browser operation; browser connection
must not be required to advance LCD presentation. Simultaneous browser output
is a later regression check, not the first performance baseline.

Start with native-size content and 320×240 integer scaling to landscape640×480.
Higher-resolution Agon modes need an explicit fit/crop/downscale policy before
being called supported. Do not silently crop. Keep Agon frame pacing separate
from panel refresh; investigate supported60-Hz timing after the vendor baseline
works, rather than changing panel timings on first power-up.

### Landscape rotation research — September 28

The Author wants landscape640×480 with the ribbon edge on the left. Preserve
this physical criterion rather than relying on ambiguous clockwise labels;
verify an asymmetric corner/text pattern before selecting the PPA angle.

LCD01-05 research finding: no supported zero-copy panel axis swap was found.
The deployed Espressif ST7701 component1.1.5 MIPI implementation installs
`panel_st7701_mirror` but no `swap_xy`; IDF5.5.5's underlying
`components/esp_lcd/dsi/esp_lcd_panel_dpi.c` also supplies no axis-swap handler.
Its test named mipi-rotate tolerates ESP_ERR_NOT_SUPPORTED for swap_xy: the name
is not evidence of supported90-degree rotation. The Sitronix ST7701S v1.4
register specification, page214, exposes scan reversal and RGB/BGR selection
in MADCTL, not a row/column exchange bit. Panel mirroring cannot substitute
for transposition. Do not transplant another controller's MADCTL bit meanings.
The module's additional controller is not proven to offer a transpose shortcut.

Sources:
1. [Sitronix ST7701S specification, distributor-hosted](https://files.waveshare.com/wiki/common/ST7701S_SPEC_V1.4.pdf), page214.
2. [Espressif ST7701 source](https://github.com/espressif/esp-iot-solution/tree/master/components/display/lcd/esp_lcd_st7701); actual examined baseline is resolved1.1.5 retained with this demo.
3. [IDF5.5 PPA guide](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32p4/api-reference/peripherals/ppa.html).
4. Installed IDF5.5.5 `components/esp_driver_ppa/include/driver/ppa.h` and the PPA/DSI example in `examples/peripherals/ppa/ppa_dsi`.

Preferred first candidate: P4 Pixel-Processing Accelerator (PPA) rotates an
RGB888 output image into an inactive native480×640 LCD buffer. DSI presents
only completed buffers; the PPA completion callback must not be confused with
scanout completion. This reuses Espressif's driver and keeps CPU pixel rotation
out of the hot path. PPA supports90/180/270-degree rotations and asynchronous
completion. It does not directly accept EDP's packed/indexed renderer formats
or RGB222, so the normal output composition/expansion still has an owner.
The repository's PresentationCompositor exposes RGB888 output; its presence
alone does not establish the correct live frame-publication integration point.

PPA is not free: input and output must be separate buffers. Full-size RGB888
rotation reads921600bytes and writes921600bytes per update, about110.6MB/s at
60updates/s, excluding composition and ongoing DSI scanout. This is arithmetic,
not a measured achieved rate. Espressif explicitly warns of shared PSRAM
bandwidth contention. Therefore hardware acceleration is the preferred CPU-cost
candidate, not a proven lowest-total-cost winner.

Alternative to compare only if necessary: fuse rotation into the existing
output conversion, avoiding an additional full-image pass. Preserve renderer
storage and semantics; benchmark tiled output writes rather than assuming
strided CPU stores are cheap. Do not create a separate CPU rotate-copy stage
as the default. At320×240, PPA can in principle combine scaling and rotation,
but pixel-exact2× replication must be verified before using its scaler: the
examined API offers no nearest-neighbor selector. Start rotation at unit scale
if filtering behavior remains unresolved. No timing changes, source changes,
flash or bench operations were performed for this research.
