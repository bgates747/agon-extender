# LCD-001 — Olimex MIPI LCD bring-up and EDP output exploration

## Executive summary

The Author has received an Olimex MIPI-LCD2.8-640X480. Olimex supplies an
ESP-IDF example for this display on the existing ESP32-P4-DevKit, so we can
explore direct local video without waiting for the P4-PC. Reuse that panel
initialization and Espressif's DSI driver; keep EDP's inherited rendering intact.
First identify the delivered panel revision: V1 and V2 require different formats
and control. Research and planning only are authorized here; no wiring, builds,
flashing or production changes have been performed.

### Revision-dependent example settings

| Item | Original WLK2802MIPI-15P / V1 | WLK2802MIPI-15P-V2 |
|---|---|---|
| Pixel format | RGB565 | RGB888 |
| Reset/backlight | PCA9536 I²C expander at 0x41 | No expander control in example |
| DSI lane rate | 1000 Mb/s, one lane | 500 Mb/s, one lane |
| DPI pixel clock | 25 MHz | 16 MHz |
| Native timing dimensions | 480×640 | 480×640 |
| Horizontal sync/back/front | 4 / 20 / 10 pixels | 4 / 20 / 10 pixels |
| Vertical sync/back/front | 4 / 14 / 8 lines | 4 / 14 / 8 lines |

The example defaults to V2. Its portrait timing dimensions differ from the
landscape product description: verify rotation and memory layout explicitly.
Derived from those totals, nominal scan rates are approximately 73.0 Hz (V1)
and 46.7 Hz (V2), not automatically 60 Hz. These are arithmetic estimates,
not measured panel rates. Olimex's older 100-fps demonstration is not an EDP
performance guarantee or a reason to overclock the delivered panel.

The example configures the P4 D-PHY supply through LDO channel 3 at 2.5 V;
that internal PHY supply is distinct from the panel connector supply. V1 uses
GPIO7/8 for I²C. Optional refresh instrumentation uses GPIO20: leave it disabled
until the actual Extender harness allocation has been checked. The README's
generic pin sketch includes two data lanes despite this panel using one;
use the actual board schematic and cable pinout, not that sketch alone.

## Scope and design boundaries

The P4 DSI peripheral drives the LCD through the board's DSI connector and FPC.
EMOS continues routing Agon VDU traffic to EDP over the existing UART path;
P4 EDP renders it and an output adapter presents the resulting pixels to DSI.
No new Agon application protocol or MOS bypass is required for initial output.

Keep upstream drawing, scrolling, clipping, sprites and palette semantics.
If DSI needs contiguous RGB565/RGB888 scanout buffers, those are output buffers,
not grounds to replace the inherited rendering storage. Document conversion,
rotation, lifetime, cache/DMA coherency and presentation ownership explicitly.
Do not hold renderer/UART locks while waiting for a display frame. Preserve
USB keyboard, recovery, SD service and browser operation; browser connection
must not be required to advance LCD presentation. Simultaneous browser output
is a later regression check, not the first performance baseline.

Start with native-size content and 320×240 integer scaling to landscape640×480.
Higher-resolution Agon modes need an explicit fit/crop/downscale policy before
being called supported. Do not silently crop. Keep Agon frame pacing separate
from panel refresh; investigate supported60-Hz timing after the vendor baseline
works, rather than changing panel timings on first power-up.
