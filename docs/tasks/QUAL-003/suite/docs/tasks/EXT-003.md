# EXT-003 — Shapes drawing-command demonstrations

**Status: All 24 pages implemented and deployed for Author review.
SHP-01/02 and keypress/Escape navigation are visually accepted. All pages
complete both the full tour and isolated runs. Reference discrepancies in
SHP-11/12/23 remain visible; see `../reference-observations.md`.**

## Objective and presentation

Build `shapes.bin`, a visual tour of the documented VDU drawing primitives
within Extender's intended Exclusive Compatible surface. Cover every defined
PLOT family, including absolute and relative movement, outlined and filled
shapes, painting modes, and the settings that affect drawing.

Use **mode 20: 512 × 384 pixels, 64 colours, 60 Hz**. Select it with
`VDU 22 20` in `/autoexec.txt` before loading the application. Mode 20 is
single-buffered; do not substitute mode 148 or switch modes inside the app.

Reserve the top 48 pixels for a high-contrast heading and description:
`SHAPES 03/24 - LINE ENDPOINTS`, the literal command family being tested,
and a short statement of the expected result. Keep the main drawing area
below that heading and a small status/footer area at the bottom. Use labelled
panels, position markers, and before/after examples where comparison matters.
The heading must remain legible throughout each test, including clipping,
scrolling, palette, and graphics-text demonstrations.

Wait for a keypress after each completed page using the vendored
`waitKeypress` routine. Any non-Escape key advances to the next test, or
finishes after the final test with the picture intact. Escape clears the
screen and returns to MOS from any page. Multi-stage pages show labelled
changes before waiting. Also support selecting one numbered page through a
MOS command-line argument for focused review, using the same key controls.
The Author explicitly requested interactive progression in place of the
original timed playback.

Most pages use pixel coordinates with scaling disabled (`VDU 23,0,&C0,0`),
origin at top left and positive Y downward. Explicitly label the logical
coordinate demonstration. Reset drawing state and seed the graphics cursor
history before each independent example; labels and guide drawing must not
accidentally become the vertices consumed by a later shape command.

## Authorized tests

The page IDs are stable review references. A command range denotes a PLOT
family; individual variants described below are the intended coverage, not
an exhaustive Cartesian product of every opcode and every geometry.

1. **SHP-01 — Absolute and relative movement; points.** Exercise PLOT
   `&04`/`&00` (absolute/relative move), `&05`/`&01` (absolute/relative
   foreground line), and point family `&40–&47`. Draw matching paths using
   absolute coordinates and signed relative offsets, including negative and
   zero offsets. Pure moves leave gaps; isolated point plots mark expected
   positions. Include relative/absolute foreground, background, and inverse
   point variants. Include the documented point commands; Extender's agent
   owns readiness review and any locally necessary skips.

2. **SHP-02 — Solid lines in every direction.** Use `&00–&07` for a fan of
   horizontal, vertical, shallow, and steep lines covering all eight octants.
   Repeat representative lines in reverse and with relative coordinates.
   Expect connected lines with the same intended endpoints in both directions.

3. **SHP-03 — Included and omitted endpoints.** Compare solid line families
   `&00`, `&08`, `&20`, and `&28`: both ends, final omitted, first omitted,
   and both omitted. Use one-pixel lines, short labelled examples, and an
   enlarged view of the actual resulting pixels. Add a shared-vertex XOR
   example to expose double-drawn endpoints. Keep guide marks outside tested
   pixels; capture/enlarge the result rather than inventing a reference image.

4. **SHP-04 — Dotted and dashed lines.** Exercise `VDU 23,6` and pattern
   length `VDU 23,0,&F2,n`, with PLOT families `&10`, `&18`, `&30`, `&38`.
   Compare pattern restart against continuation over joined segments, all
   endpoint variants, several lengths, and reset-to-default length zero.
   Expect visible phase continuity only in the continued-pattern examples.

5. **SHP-05 — Line thickness.** Use `VDU 23,23,n` with widths 1, 2, 4, and
   8 on solid lines and supported curved outlines; show a filled-shape control
   whose area should not change. Keep omitted-endpoint tests at thickness 1,
   since the documentation cautions about thicker variants. Restore width 1.

6. **SHP-06 — Triangles: outline and fill.** Outline with connected lines;
   fill using `&50–&57` and the documented three-point cursor history. Include
   opposite vertex orders, a thin triangle, and a fan of adjacent triangles
   drawn with XOR. Expect complete interiors and shared fan edges without
   cancellation cracks, following the documented modern rasterization rule.

7. **SHP-07 — Rectangles: outline and fill.** Outline with four line segments;
   fill using `&60–&67`. Compare opposite-corner order, relative and absolute
   final corners, a one-pixel-wide rectangle, and a one-pixel-high rectangle.
   Label the intended inclusive bounds so extent errors are visible.

8. **SHP-08 — Parallelograms.** Use `&70–&77` with the first and third
   supplied points as opposing corners; the VDP derives the fourth corner.
   Show left-leaning and right-leaning filled shapes alongside independently
   outlined equivalents. Repeat one example using a relative final point.

9. **SHP-09 — Circles.** Compare outline `&90–&97` and fill `&98–&9F` at
   several radii, using the centre and a circumference point. Include an
   off-axis radius-defining point and relative positioning. Expect matching
   extents for outlined/filled pairs and circular appearance in pixel space.

10. **SHP-10 — Ellipses.** Exercise outline `&C0–&C7` and fill `&C8–&CF`.
    Show wide, tall, and sheared ellipses, marking the centre, same-height
    outer point, and upper/lower point used by the three-point contract.
    Expect the sheared examples to differ visibly from axis-aligned ellipses.

11. **SHP-11 — Arcs.** Use `&A0–&A7` for quarter, half, and major arcs.
    Label the supplied start, centre, and end-direction points; include an
    end-direction point not on the circumference. Follow the documented
    anticlockwise sweep, accounting for the selected coordinate convention.
    Expect an open curve without chord or radius edges.
    The implementation also repeats the examples with the reference VDP's
    centre/start/end ordering, explicitly labelled alongside the documented
    start/centre/end ordering. Neither interpretation is silently substituted.

12. **SHP-12 — Segments and sectors.** Compare `&A8–&AF` with `&B0–&B7`
    for identical start/centre/end geometry, including minor and major sweeps.
    A segment closes with a chord; a sector closes through the centre.
    Display reference radii/chords beside the examples to make that distinction
    visible without interfering with the shape's graphics cursor history.
    Minor and major examples use both documented and reference point orders,
    for the same reason as SHP-11.

13. **SHP-13 — Horizontal line fills.** Use four isolated panels for families
    `&48`, `&58`, `&68`, and `&78`: fill left/right to non-background, right
    to background, left/right to foreground, and right to non-foreground.
    Prepare deliberately different foreground, background, and third-colour
    runs. Mark each seed and expected stop. Follow each fill with a relative
    line to demonstrate the updated right-edge graphics cursor position.

14. **SHP-14 — Flood fills.** Compare `&80–&87` and `&88–&8F` using closed
    enclosures, third-colour islands, and a gap leading to a larger region
    bounded by the viewport. Expect different stopping rules: non-background
    versus foreground boundaries. Keep the fill viewport below the heading.

15. **SHP-15 — Experimental filled paths.** Use `&D8–&DF` to draw convex
    and concave polygons with more than three vertices. Mix relative and
    absolute foreground commands in one path; demonstrate explicit closure
    with a following non-path command. Send each complete path uninterrupted,
    with no intervening labels or delays. Label this page EXPERIMENTAL; avoid
    claiming a fill rule for self-intersecting paths that the docs do not define.

16. **SHP-16 — PLOT foreground, background, and inverse variants.** Compare
    low-bit variants 1/2/3 and 5/6/7 on identical prepared panels, using lines
    and filled shapes. Foreground/background select their respective GCOL
    settings; inverse temporarily overrides the painting mode. Drawing the
    same inverse shape twice should restore the original pixels.

17. **SHP-17 — All eight GCOL operations.** Use `VDU 18` modes 0–7 in
    labelled panels: set, OR, AND, XOR, invert, no-op, AND inverse, OR inverse.
    Draw the same overlapping geometry over known colours, with both
    foreground and background paint settings represented. Show expected colour
    swatches based on actual physical colour values, not assumed logical-index
    arithmetic. XOR/invert twice restore; no-op leaves the panel unchanged.

18. **SHP-18 — Colour mapping and reset.** Display all 64 logical colours.
    Exercise `VDU 19` with both a physical colour number and explicit RGB,
    then `VDU 20`. Draw labelled samples before remapping, after remapping,
    and after reset. In mode 20, remapping affects subsequent drawing rather
    than recolouring pixels already on screen. Reserve heading colours from
    the remapping experiment and use RGB values representable by Agon's palette.

19. **SHP-19 — Graphics origin and logical coordinates.** Use `VDU 29` to
    repeat one motif at different origins, including negative local positions.
    Compare pixel coordinates with `VDU 23,0,&C0,1` logical 1280×1024
    coordinates, demonstrating the different Y direction and scaling.
    Restore pixel scaling and the standard origin before the next page.

20. **SHP-20 — Viewports, clipping, and clears.** Exercise `VDU 24`, `28`,
    `16` (CLG), `12` (CLS), and `26`. Draw shapes crossing all four edges of
    a smaller graphics viewport; compare valid one-pixel-wide/high viewports.
    Clear graphics and text subwindows separately. Expect inclusive clipping,
    no damage to surrounding reference artwork, and reset origin/viewports
    after VDU 26. Restore the heading viewport immediately after resets.

21. **SHP-21 — Viewports and origin from graphics history.** Use system
    commands `&9C`, `&9D`, `&9E`, and `&9F` to define text/graphics viewports
    from cursor positions, set the origin, then move the origin and viewports
    together. Use a boxed motif and text to show the resulting displacement.
    Include partially off-screen viewport coordinates to demonstrate the
    documented clipping difference from the direct viewport commands.

22. **SHP-22 — Rectangle copying, moving, and scrolling.** Use an asymmetric
    multicolour source for `&B9` relative move, `&BA/&BB` relative copy,
    `&BD` absolute move, and `&BE/&BF` absolute copy. Include nonoverlapping
    and overlapping destinations. Copies retain the source; moves clear the
    vacated source using background colour. In a separate panel exercise
    `VDU 23,7` graphics-viewport scrolling left/right/up/down at pixel offsets
    and zero's character-step behavior. The heading stays stationary.
    Destination coordinates identify the bottom-left of the copied rectangle,
    including in pixel mode; the lower copy/move row overlaps its source.

23. **SHP-23 — Bitmap shapes and graphics text.** Create a small asymmetric
    RGBA2222 bitmap with transparent areas in memory, upload via buffered
    commands, select/create it using `VDU 23,27,&20/&21`, and exercise bitmap
    PLOT `&E8–&EF` with relative/absolute foreground, background, and inverse
    variants. Compare direct bitmap drawing (`VDU 23,27,3`) with PLOT clipping.
    Print labels at graphics positions with VDU 5, then return to VDU 4 for
    the heading. No external image/font assets are required for this page.

24. **SHP-24 — Reusable drawing, transforms, and context restoration.** Upload
    one vector motif as a command buffer, call it repeatedly at distinct
    origins, and compare it with the directly emitted motif. Exercise context
    save/restore (`VDU 23,0,&C8,3/4`) around temporary colour, viewport, and
    origin changes; subsequent drawing must recover the saved settings.
    In a separate labelled panel, use the buffered matrix API and bitmap
    transform selection (`VDU 23,0,&96`) for identity, scaling, rotation, and
    shear of the SHP-23 bitmap. These transforms apply to bitmap plots, not
    the vector primitives. Clear only application-owned buffers on completion.

## Scope and implementation boundaries for review

1. The Author directed that currently unsupported VDU commands remain in the
   compiled tests. Extender's agent will review the actual tests, prepare
   support, or explicitly skip commands for a local reason. In particular,
   include point plotting (`&40–&47`) despite its omission from the current
   enumerated Extender PLOT inventory. No local support filter is applied.
2. The plan covers drawing primitives and closely related state. Audio,
   sprite animation, tile layers, Copper display effects, and a comprehensive
   font-management suite are separate applications rather than extra Shapes
   pages. Undefined PLOT families and unsupported Acorn pattern-fill GCOL
   modes are excluded. Bitmap plotting and its transforms remain here because
   they are part of the documented PLOT surface.
3. Assemble through the vendored API set. Add missing wrappers as needed for
   these approved pages; do not treat existing `ret` placeholders as working
   APIs. Review every exercised packet builder for exact byte widths and
   preserve the vendored-source provenance when making any necessary fixes.
4. Use MOS/EMOS output calls exclusively and `mos_getkey` through the imported
   `waitKeypress` routine for page navigation. Bound protocol-response waits;
   keypress waits intentionally remain blocked until input arrives. Do not
   use the inherited direct timer/interrupt setup helpers.
5. Build to `tgt/shapes.bin`; keep Hello World alongside it. Supporting files,
   if later needed, belong under `tgt/assets/`. Select Shapes with an explicit
   reviewed startup update: mode 20, `cd /extender`, `load shapes.bin`, `run`.
   The implemented `select`/`run` Make targets choose startup explicitly;
   ordinary deployment preserves it.
6. Each page starts from an explicit known state, flushes queued work before
   observation (`VDU 23,0,&CA`), and uses `&C3` only as a VSYNC wait in mode
   20. The exit path restores normal text output, cursor visibility, colours,
   origin, viewports, pattern/thickness, and bitmap-transform state without
   switching video mode. Restore any contexts/resources owned by this app.

## Planned validation and acceptance

1. Assemble with listing and symbols; audit every newly exercised VDU packet
   against the official parameter layout, especially signed coordinates and
   exact 16-bit fields in ADL mode.
2. Use pixel queries (`VDU 23,0,&84`) for a small set of unambiguous cases:
   pure-move gaps, line endpoints, clipping, no-op, inverse-twice, and copy
   source retention. Clear completion flags before queries and bound waits.
   Report query failures separately from visual observations; never let a
   missing reply prevent tour completion or clean exit.
3. Check each page's visible expected result in the stock reference emulator,
   including both full-tour and isolated-page execution. Present staged pages
   for Author review rather than calling successful assembly a rendering pass.
4. Keep experimental-path results identifiable. Extender's agent owns
   support decisions for documented commands absent from its inventory.
   Do not set whole-app PASS merely because the tour finishes.
5. After emulator review, retain physical Extender results as a separate
   qualification record. Emulator-related changes remain uncommitted until
   the Author has tested them and explicitly approved committing.
