# NET-005 — Interactive Wi-Fi BBS fixture

Give Smith a small, useful Console8 Wi-Fi test: type commands, read the Pi's time
and uptime, and leave persistent notes. The Console8 runs Radiotux's unchanged
terminal; the Pi supplies the new application. Publish this plan before code.
The physical Console8/ESP8266 path remains a manual Author test.

## Authority, scope and state

On 2026-11-05 Smith selected the proposed tiny Pi BBS and instructed Extender to
write the task, commit/push its plan, then execute. This releases the host-side
fixture implementation, bounded local tests, package preparation and explicit
Pi listener startup. It does not lift the prohibition on remote Console8 access.
No firmware, MOS/VDP source, wiring, startup, service-on-boot or emulator changes
are selected. Existing bench leases remain untouched.

The initial host command set is `help`, `time`, `uptime`, `note TEXT`, `notes`
and `quit`. Notes persist on the Pi. This is a plain TCP text service, not Telnet
and not a Codex session. No shell commands, model/API calls, automatic agent
notifications, async UART adaptation, OTIRX or new wire checksums belong here.

UART1 must not be borrowed from an active Extender installation elsewhere.

## Bounded research précis

1. Read-only Radiotux baseline commit
   `e265db1de57c49142420324945c666049dc1ec53`: `minicom/Agon-Terminal.man`,
   `minicom/src/{main,terminal}.c` and `minicom/src/common.h`. Terminal uses
   MOS UART1 at 115200 8N1, flowcontrol0/eir0; Enter sends CRLF, Ctrl+Q closes
   UART and exits, Ctrl+E changes local echo. No new Console8 build is needed.
   The selected existing `minicom/bin/minicom.bin` SHA256 is
   `6f0c41273eb4ab479ad39ac0bde2cd3550f4403cbc8afec5c4e15a0fae8f9d4c`.
2. Official read-only Agon documentation: `agon-docs/docs/mos/API.md`, calls
   0x15–0x18 for UART1 open/close/read/write. NET-002 retains the source baseline
   and reuse limits. This task changes no MOS interface or client code.
3. Espressif's [ESP8266 AT instruction set v1.5.4](https://www.espressif.com/sites/default/files/4a-esp8266_at_instruction_set_en_v1.5.4_0.pdf),
   Wi-Fi `_CUR` commands and TCP/IP `CIPMUX`, `CIPSTART`, `CIPMODE`, `CIPSEND`
   and passthrough escape: choose volatile configuration, identify actual module
   firmware first, and stop on unsupported commands. This manual is a reference,
   not proof of the connected module's firmware or compatibility.
4. Passthrough can reconnect after TCP closure; `quit` closes the Pi connection,
   not necessarily the modem's data mode. Document `+++` without Enter and the
   required pause/AT cleanup, with a manual module restart fallback if escape
   is not recognized. Ctrl+Q alone is not modem cleanup. Do not hide this limit.
5. The unchanged terminal has a short workspace and limited scrolling. Keep
   help/notes replies short and ASCII; do not stream unsolicited output. Capture
   remains off so no root-level `capture.txt` is created by the fixture procedure.

## Host implementation checkpoint

The experimental fixture identity is `wifi-bbs-r01`; generated packages receive
their own UTC build timestamp without changing any firmware version. The Pi
implementation passes eight real loopback methods in 0.286 seconds, covering all
six commands, fragmented input, persistence/restart, second-client refusal,
invalid input, EOF/quit and actual CLI/SIGTERM closure. No Console8 traffic was
generated. Detailed selected-source hashes and scope are in
[HOST-CHECKS.md](NET-005/HOST-CHECKS.md).

Implementation gotcha: current asyncio server closure waits for client
transports. Stop cancels/joins the admitted handlers before waiting for listener
closure; waiting in the opposite order stalled an idle-terminal shutdown. The
actual stop and SIGTERM tests exercise the corrected order. No UART or protocol
workaround was added.
