## Implementation boundary

The core's explicit disconnect/connect lifecycle is retained. The HTTP task
replaces its client under a dispatch mutex that excludes worker acquisition
and queueing. Exactly one queued callback is allowed and retains the original
socket identity. A stale callback drains before the worker prepares a new
viewer's frame. The HTTP task already serializes actual sends and handshake/
close callbacks. Successful HTTP shutdown clears the pending callback record
only after the task stops. No changes to rendering or browser scripts.

VT02 host regression exercises actual adapter method bodies against mocked IDF
calls and the real service core/lease. Sanitizers cover idle, pending credit,
queued sends, delayed old cleanup, reconnect, worker acquisition race and queue
failure. The existing core may still return Busy when called without adapter
replacement; this is intentional ownership separation.

## Discovery amendment — static HTTP connections block admission

Physical tests reached viewer A, but B stayed at connecting until A's browser
was closed by test cleanup. Passive serial from the controlled repeat shows
A receiving248frames, no replacement callback, then B admitted only at cleanup.
The pinned IDF default has seven HTTP sessions and LRU eviction is disabled;
multiple browser contexts retain enough idle asset-download connections to
exhaust admission before a new WebSocket handshake can reach the adapter.

1. [x] VT02a: Close static-asset HTTP connections after their response. Preserve
   the live WebSocket and existing RPC contracts; no broad LRU eviction or
   larger unbounded client pool. Add response/close-path host coverage and rerun
   the same physical test with both independent browser contexts.

This is necessary for the requested new-viewer admission, not renderer work.
The capture now preserves per-viewer state/screenshots on failure. A separate
repeat overlapped opening the USB serial observer and P4 startup; treat that
repeat as invalid, not a proven firmware crash. Controlled serial acquisition
before reboot/game launch is used for the informative repeat.
