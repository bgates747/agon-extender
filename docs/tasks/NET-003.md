# NET-003 — Generic application network messaging framework

Native Agon applications need persistent bidirectional messages to host services.
Existing Extender video, keyboard, controller and file-transfer endpoints do not
provide that interface. Build a small reusable framework with bounded storage and
explicit ownership, preserving scarce eZ80 flash/cycles and existing display/input.
MechAgon is the first consumer; its game protocol and server stay in its project.

## Ownership and invariants

| Actor | Owns |
|---|---|
| P4 network worker | Socket/connect/close lifetime, bounded network RX/TX, stream framing, link-loss/failure state; never direct UART writes |
| P4 console owner | Complete packet serialization with keyboard/VDU service traffic and delivery to the network worker |
| EMOS | Caller admission and lifetime, ordinary VDU routing and shared physical transport, bounded safe copying/correlation; minimal resident logic |
| Application library | Request/result interpretation, nonblocking send/receive/poll API and consumer-owned buffers; no raw UART/GPIO |
| MechAgon Pi adapter/application | Tank Royale WebSocket/JSON/schema/turn rules, bot logic and arena rendering |
| Extender | Generic service/transport framework, independent reusable checks and integration contract |

Do not reuse controller or SD service identities for arbitrary network payloads.
Do not add CRCs or substitute software checksums to EMOS/P4/application traffic.
No per-byte handshake; network and shared-transport backpressure must let the
caller do useful work. Packet admission/completion is distinct from remote
application consumption. No transparent reconnect/replay of uncertain payloads.
No general callback ABI is assumed available. No unbounded task, queue or heap
allocation in the core; no game schema or tick-rate constants in generic code.

## First implementation boundary

The maintained, default-off source lives under
`../../vdp/video/extender/network/messages/`. Its platform-neutral channel has
compile-time capacity parameters, separate bounded TX/RX FIFOs, exclusive
boot-local ownership generations and no implicit reconnect/replay. Explicit
close retires queued/partial data. Faults preserve complete RX for ordered drain
and retain uncertain TX count for diagnostics; sending cannot resume. The
nonblocking pump has operation/byte budgets and preserves fair direction order
across calls. Its numeric-IPv4 TCP adapter creates no worker or Ethernet owner.

The prototype prefix is four-byte little-endian length, with no published ABI
version or default hardware message ceiling selected. Tests use256-byte/two-slot
and1024-byte/four-slot profiles; these are allocation probes. P4 placement,
actual runtime storage/stack, DNS policy and eZ80 message fragmentation remain
integration concerns. No application-facing gateway or end-to-end facility is
claimed. No generic completion callback has been invented.

Existing controller/video/storage tests provided actual-component/fake-adapter
patterns. Video latest-frame credit and SD checksum mailboxes are incompatible
with the required ordered/no-checksum message contract, so the core does not
reuse those semantics or add dependencies on either service.
