# NET-003 — Generic application network messaging framework

Native Agon applications need persistent bidirectional messages to host services.
Existing Extender video, keyboard, controller and file-transfer endpoints do not
provide that interface. Build a small reusable framework with bounded storage and
explicit ownership, preserving scarce eZ80 flash/cycles and existing display/input.
MechAgon is the first consumer; its game protocol and server stay in its project.

## Ownership and invariants

| Actor | Owns |
|---|---|
| P4 network worker | Socket/connect/close lifetime, bounded network RX/TX, stream framing, link-loss/failure state; never direct UART writes |
| P4 console owner | Complete packet serialization with keyboard/VDU service traffic and delivery to the network worker |
| EMOS | Caller admission and lifetime, ordinary VDU routing and shared physical transport, bounded safe copying/correlation; minimal resident logic |
| Application library | Request/result interpretation, nonblocking send/receive/poll API and consumer-owned buffers; no raw UART/GPIO |
| MechAgon Pi adapter/application | Tank Royale WebSocket/JSON/schema/turn rules, bot logic and arena rendering |
| Extender | Generic service/transport framework, independent reusable checks and integration contract |

Do not reuse controller or SD service identities for arbitrary network payloads.
Do not add CRCs or substitute software checksums to EMOS/P4/application traffic.
No per-byte handshake; network and shared-transport backpressure must let the
caller do useful work. Packet admission/completion is distinct from remote
application consumption. No transparent reconnect/replay of uncertain payloads.
No general callback ABI is assumed available. No unbounded task, queue or heap
allocation in the core; no game schema or tick-rate constants in generic code.

## Bounded research précis and reuse

1. Official MOS documentation: `../../../../agon-docs/docs/mos/API.md`, UART1
   operations0x15–0x18 and callback0x1D. These are physical UART operations, not
   sockets. EMOS already owns that link; applications cannot seize it. Review
   official source only for an unanswered implementation contract; keep official
   checkouts read-only and record any selected baseline before using its code.
2. Existing resident gateway: `../../../agon-emos/docs/emos-v1-contract.md` and
   `../../../agon-emos/src/emos.c`. Reuse gateway dispatch/caller validation and
   current packet owners; do not grow a second registry or a game interpreter.
3. P4 network interfaces: `../shared-p4-services.md`,
   `../../vdp/video/extender/network/{wired_network_service,http_video_service,devkit_ethernet}.*`.
   These provide existing network ownership and a server, not outbound Agon sockets.
4. Reusable ownership patterns: `../../vdp/video/extender/network/opaque_message.*`
   and `browser_video_service_core.*` use bounded lifetime/complete-or-error
   delivery; their video credit/latest-frame semantics do not fit ordered messages.
   Storage's application mailbox is specialized and includes historical checksum
   work; do not copy that wire format or integrity path.
5. Existing tests under `../../tests/network/` and `../../tests/controller/`
   demonstrate actual-component host compilation and fake transport boundaries.
   Extend their style and reuse simple utilities where appropriate; do not build
   a second model that never executes the proposed production core.
6. Retained latency: `INPUT-002/R14-COMPARISON.md` and
   `../testing/controller-latency.md`. These establish only historical
   host/P4 UDP ACK timing, not application delivery or a game deadline. Bulk SD
   rates, controller mailbox lengths and old socket ceilings are not new limits.
7. Initial source review: Extender5115ad3f83ebe47e8724657648959dd03cd57de3,
   EMOS08301e6d28f5cdd6a8bb01aa6806b6d4ddaf816c. Neither identifies installed

   D01 and consumer payload/lifecycle constraints without inventing a tick rate.

   nonreused incarnation, close/fault invalidation and stale-completion rejection.
