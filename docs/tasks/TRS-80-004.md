# TRS-80-004 — Shared HTTP/browser-video transport

## Executive summary

Author authorized task definition and implementation on 2026-09-26 after the
TRS-80 VIDEO-01 request. Extract the maintained socket/credit/lease adapter so a
detached consumer injects its frame provider and web assets without importing
VDP/EMOS or starting Ethernet/SD. Preserve console behavior and tested partial-send
handling. Initial consumer needs raw EVF1; console compression remains supported.
No bench switch, firmware promotion or guest integration is part of this tranche.

## Frozen work contract

T04-01 [ ] Extract owner-maintained HTTP/video class; existing console uses the
same handlers/send lifecycle. Consumer owns startup serialization, periodic pump,

T04-04 [ ] Update maintained shared-service guide and hand peer a committed pin,
source list and test results. Preserve selected production and installed peer

## Bounded source basis

Existing wired_network_service.cpp owns ESP-IDF socket work, callbacks and F003
short-write workaround; browser_video_service_core owns one-client/credit leases.
OpaqueMessageProvider supplies immutable message views. embedded_assets.hpp is
plain asset metadata; rendering and VDU semantics are outside this extraction.
Current framework is Arduino 3.3.11 / IDF 5.5.5. TRS-80 owns VIDEO-01 pattern,
page and later MAME adapter. No MOS/VDP API, ABI or hardware contract changes.

Keep tracked paths portable; private peer/bench identities belong to mailbox and
machine-local records. This task is a bounded implementation dependency of
TRS-80-003, not completion of its native-eZ80 feasibility or shared-media gates.
