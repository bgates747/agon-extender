# BENCH-020 instruction cutover

The maintained [Olimex bench guide](../../operations/olimex-bench/README.md)
is the single checkout-through-check-in entry. The Extender, shared
environment, and consumer redirects were updated after the qualified cold
run. The old registry had no current owner or waiting reservations. The
scheduler received the final guide and continues the direct-chat FIFO used in
the rehearsal.

| Existing instruction route | Correction |
| --- | --- |
| Shared Agon instructions, environment and scheduling index | Send the reader directly to the Extender guide for physical Olimex. Retain Oryx, Pi5 compiler and other independent routes. |
| Shared physical scheduling guide and its older path | Retain a direct redirect. Retain the tool and old registry for historical receipts and any incumbent handoff. End routine instructions to call the legacy helper. |
| Extender AGENTS, handbook, operation index and tool index | Send ordinary Olimex operators to the single guide with their commissioned local binding. Retain the general project instructions for builds, API research, emulators and other non-bench work. |
| Old Extender scheduler guide and forwarding instructions | Replace routine scheduling steps with a direct link. Archive the first assignments, grant-helper examples and training as history. The scheduler follows the guide and performs the direct queue exchange. |
| Old firmware procedure and its summaries in test, appliance, rollback and qualification documents | Remove conflicting bench policy. Link the current guide for production per processor, custom write and validated restoration. Keep fixture, tooling and general recovery mechanics where they belong. |
| Bench completion, serial capture, reset, SD and MOS recovery | Keep the technical operations needed for specific faults or jobs. Send custody, normal operator sequence and check-in to the guide. Honor the guide’s current attended stop rule. |
| Active project entry points identified by BENCH-018 | Replace the old scheduling branches and dated occupancy with a direct link. Keep case-specific evidence and any explicit human-start restriction. Review and change each active instruction with the owning workspace. |
| Previous tasks, immutable run logs and old worksheets | Keep actual receipts and decisions traceable. Remove live-entry links or clearly identify the specific dated run at the point of discovery. |

The current entry points reach this guide directly. A production-only offline
check listed stage, run and handback. The qualified custom path installed and
restored only the named processors, with a complete readback per write.
Routine scheduling used the operator's chat identity, reservation request and
check-in. The scheduler confirmed each completed check-in. The independent
FIFO scenarios stay deferred to real jobs.
