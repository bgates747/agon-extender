# P4 native row scanout and exact 320×240 pixel doubling

**Plan for Smith's review, November 21, 2026.** Let P4 display DMA determine when EVDP reads the next native rows. Have one producer compose those rows once, convert their colours and write directly into storage DMA can consume. Preserve the stock drawing and buffering contract for every application. Smith selected exact 2× pixel replication for 320×240. The driver design, implementation and physical test are pending review. Nurples supplies one mode-20 motion case. The separate blackout investigation is deferred.

## Row production and ownership

1. **Match stock at the sampling boundary.** Use a P4 DMA block retirement to identify freed storage. Its interrupt timestamps and posts a bounded request containing mode epoch, frame, block and slot. One task owns sequential stock row preparation and the Copper cursor. Only the task takes the native guard. It reads each visible logical row, applies the existing depth-specific palette/Copper and sprite/cursor rules once, and releases the guard before RGB output work. Never retain a mutable bitmap, row pointer or palette reference past the guard. For cropping, advance any required off-screen Copper state in source order. Prove a cheaper skip against stock before omitting such work. Match stock software-sprite drawing and hardware-sprite composition without a second overlay pass. [Stock worker and row guards](../../../vdp/video/extender/display/stock_runtime_controller.hpp) · [Stock compatibility oracle](../PORT-003/stock-backend-r2/README.md)
2. **Write the final pixels once.** Convert native signal lanes to the panel's actual three-byte channel order. For 320×240, fetch one decorated source pixel, convert once and emit the horizontal pair. Prefer having two DMA output lines reference the same finished row if the P4 descriptor, alignment, FIFO and lifetime rules support it at lower cost. The producer owns that row again only after both reads retire. Otherwise benchmark direct writes to both final rows against expanding one line and copying its completed bytes once. Both must produce identical RGB triples. Initialize black borders on slot allocation or geometry change. Preserve 640×240's existing vertical-only repetition, 512×384 at 1:1 with 86-pixel sidebars, and the existing center/crop rules elsewhere. Keep selection of the 848 carrier for 320×240 independent of the old PPA build flag. [Geometry](../../../vdp/video/extender/display/hdmi_geometry.hpp) · [Carrier policy](../../../vdp/video/extender/display/hdmi_timing.hpp)
3. **Preserve drawing phase as well as row order.** For each stock depth, establish when the final visible logical rows are sampled, queued drawing becomes eligible and the first rows of the next frame are read. Stock VGA64 has a four-row ring and prepares two rows at a time. The inherited P4 schedule can request blocks 0 and 1 of the next frame during the current frame. Blindly using those requests can freeze old terrain at the top for another frame. Specify frame/block descriptors and phase markers for startup, last visible rows, vertical blank, wrap and first visible rows. Gate next-frame reads so they cannot precede the intended drawing opportunity. Issue the drawing wake once near the stock-equivalent hardware raster position, after the final relevant rows have been staged. Advance the public frame count once per physical frame, independently of work completion. Preserve stock queue ordering, explicit waits, immediate drawing in double-buffered modes and queued swaps. Track which logical bank each row uses across a swap. Stock single buffering permits writes during active display. It supplies no promise of a frozen whole image. If the 32-row schedule shifts that boundary too far, test a smaller block or finer hardware event with its own interrupt cost and tighter reuse deadline before enabling it. [Retirement scheduler](../../../vdp/video/extender/display/rolling/strip_runtime.inc) · [Stock and P4 timing](STOCK-SCROLL-TIMING-REVIEW.md)
4. **Prove every handoff.** Track slots as free, filling, DMA-visible/ready, and in use. Establish cache visibility before publishing the unique generation. Reject stale, duplicate, missing, overlapping and late completions. Prime required slots before the first DMA fetch. Keep the refill path allocation-free and nonblocking in the ISR. Bound worker scheduling and mutex-owner delay, including long scrolls and clears. If one legal primitive can hold the lock past the deadline, locate that interval and redesign access with explicit lifetime and stock ordering before qualification. A missed slot stops that trial and preserves the first fault. For mode changes, stop admission, invalidate the epoch, cancel/join workers and callbacks, observe actual DMA channel stop, then free or rebind storage. Exercise late callbacks, carrier restart, failed setup and rollback. Retain the tested stop-before-free protection. [Prior DMA stop proof](SIZE01.md)

## Redundant-work audit and removal criteria

Inventory each executing producer and consumer on the pinned build. Count reads, writes, nominal byte ranges, calls and reserved bytes separately. For each proposed deletion, inspect the built configuration, compare the linked hot path with its stock equivalent and verify the counters during matched tests. DMA transfer bytes, CPU copies and cache-maintenance ranges are different quantities. The following counts are payload arithmetic per completed conversion unless marked as allocations.

The P4 allocates that source when initializing the scaler, even on other geometries in this build. | Remove the source allocation, its write/read, bilinear operation and completion wait. Produce 76,800 logical pixel colours once. Exactly 307,200 image samples go to the display. A full carrier scan reads 1,221,120 RGB bytes including borders. No duplicate native sampling for a repeated row. |

DMA still needs the final pixels. Target zero intermediate full-frame RGB writes and zero concurrent writes to scanned storage. Verify the derived driver can omit unused frame allocations and that its destroy/failure paths own exactly what they allocate. |
| Historical rolling copier | A different backend copies a pre-expanded RGB background into SRAM with DMA2D, then can composite staged sprites. | Reuse safe descriptor/retirement logic. Retain keyboard/network/status semantics, and preserve snapshot ownership in builds that offer browser video. Account for PSRAM and internal DMA-capable SRAM independently. |
| Row scratch, borders and repeated work | Stock needs a private writable signal row for some decorations and packed-depth expansion. The candidate's full clear is conditional on target/geometry change. | Keep a bounded scratch row when the decorator needs it. Examine a fused read/format path only where the source lifetime, palette/Copper and overlays permit it and timing improves. Test shared immutable rows for padding and vertical repeats. Avoid per-frame border clears, redundant colours/format conversions, per-refill heap work, duplicate wakeups and per-row logging. Verify row visits, composition calls, physical reads and written bytes by mode. |

The current driver zeroes and cleans new panel buffers during allocation. The publisher can then clear the same new target on its first geometry visit. Eliminate that second initialization when the driver has established zeroed, DMA-visible contents. On reused slots, clear newly exposed border spans whenever their role changes, including top and bottom letterboxing. Confirm a moved or shrinking picture leaves no old pixels. Check repeat descriptors before choosing them: one 848-pixel RGB row is 2,544 bytes, while the current block design assumes a multiple of 64 bytes. More descriptors, interrupts or cache work can cost more than a local row copy. Compare both designs at the same timing and ownership guarantees. For mode 8 the candidate wrapper's full-destination clean and invalidate requests each span 1,221,120 bytes. Trace the pinned SDK's source clean (230,400 bytes), destination invalidation and the panel submission's row clean separately. These are requested ranges. Cache-resident data and actual external-bus traffic must be measured separately. For mode 20 the writable signal-row scratch totals 196,608 bytes written per complete pass. Check whether a read-only, overlay-free fast path can bypass that copy without holding the native lock through RGB expansion. Otherwise keep the scratch and record its cost. Check the browser provider, status and teardown callers before replacing the pool's eager backing. Separate registration/metadata from storage when no pixel consumer is active.

Inventory the remaining hot work from parser through DMA on both CPUs: repeated traversal of bitmap/sprite lists, duplicate palette lookup, clearing/copying unaffected pixels, recursive locking, wakeups with no useful work, abandoned conversions, and readback for status. Use source/call counts to establish which ones actually execute. Give each observed item a disposition, reader/writer, bytes or cycles, and a correctness witness. For each removed path the corresponding allocator/copy/convert/sync counter should reach zero in its applicable arm. Verify the same pixels, waits and useful drawing throughput afterwards. For retained work, name the consumer that still needs it. Diagnostics aggregate in RAM and report outside the timed run.

Retain the intrinsic costs of stock drawing, final carrier reads, valid slot ownership and stateful row effects in the accounting. A larger ring spends internal SRAM and increases sample lookahead. Recomputing a static scene at raster cadence can also cost more CPU than repeating a completed HDMI frame. Compare quiet CLI, held pattern and moving scenes. Any proposed reuse of unchanged content must include palette/Copper, cursor, independently moving sprites, bank swaps and mode generation in its validity rule. Start with the simple correct producer and use measured dominant costs to decide further optimizations. ## Refill budget and what would prove it

Initial model for review uses three slots of 32 physical rows. Both carriers use 1,104 clocks per line at 240/7 MHz, giving 32.2 µs per line. During active scan a filled slot is consumed every **1,030.4 µs**. Two intervening slots give a nominal **2,060.8 µs** from retirement to reuse in the active region, before accounting for FIFO prefetch and event latency. Keep the existing **1,600 µs maximum** on this geometry. The nominal difference of 460.8 µs is budget for uncertainty and physical lead, not measured margin. A producer taking 1,500 µs for every slot could meet one isolated deadline and still fall behind during active scan. The earlier static mode-20 conversion averaged 29.445 ms for one image, or about 2,454 µs per 32 rows if divided evenly. That is a feasibility warning for the current conversion loop. A new producer needs measured row and lock costs; removing a destination copy alone does not prove it fits. [Carrier timings](../../../vdp/video/extender/display/hdmi_timing.hpp) · [Slot constants](../../../vdp/video/extender/display/rolling/strip_config.h)

| Carrier | Blocks per frame | Native rows per 32 output rows | One RGB slot / three, bytes | Nominal vertical blank |
|---|---:|---|---:|---:|
| 848×480 | 15 | 16 at 320×240 or 640×240, 32 at 640×480 | 81,408 / 244,224 | 1,191.4 µs |
| 684×384 | 12 | 32 at mode 20's 512×384 | 65,664 / 196,992 | 4,282.6 µs |

1. **Define real start and finish.** For each slot obtain the hardware retirement time, ISR delivery, worker dispatch, native-lock acquisition, last source row read, final store, required cache completion, ready-tag publication and earliest possible next DMA fetch. The inherited timer starts at software request creation. Its ready check can run after the next transfer has started. Capture actual DSI DMA block/descriptor progress with a supported hardware witness, or derive conservative hardware bounds from the pinned DMA/FIFO behavior and validate them against a common-clock trace. Include timestamp resolution, worst IRQ delivery delay, skew and probe overhead. A GPIO toggle at ISR entry alone measures software arrival. If hardware retirement/reuse cannot be observed or conservatively bounded, report *physical deadline unverified*. Do not substitute a DMA2D completion for DSI scanout progress.
2. **Measure sustained service and tails.** For each mode/workload/transition count every expected block, record queue high-water, per-slot maxima, p99/p99.9, minimum ready-to-fetch lead and worst contiguous active-line burst. Keep same-refill phase timings for the worst case and first failure in bounded storage. Keep steady-state, startup/preload, frame wrap and teardown separately attributable. Verify positive physical lead after error bounds and worst hardware-retirement-to-DMA-visible time including error ≤1,600 µs. Require every active burst to return its slots on schedule with bounded queue depth. Check that lookahead stays in the declared range and that every finished frame has the expected blocks and exactly one clock tick. Check native row composition counts explicitly: 240 for 480 physical image rows in mode 8, and 384 for 384 in mode 20. Check the first two slots and the last-to-first seam with a moving landmark and scroll/bank generation tags. Tighten the budget if earlier fetch requires it. Hot-path logs could change the result, so use counters and a bounded trace, then repeat with production-level instrumentation and report its cost.
3. **Prove detection works.** First exercise delayed worker dispatch, long native lock, late ready, wrong generation, delayed callback and stopped/restarted DMA in the host descriptor model. In a separately commissioned diagnostic run, deliberately delay one tagged refill and verify the first-fault latch, slot identity, stop behavior and captured phases. Keep injected runs separate. For passing workloads require zero budget violations, underruns, invalid descriptors, late/duplicate generations, overwritten active slots, dropped requests, unexplained frame repeats and missing evidence. Averages or a steady 60 Hz frame counter cannot establish this result. Previous builds saw **1,641 µs** on 8→20 and **1,671 µs** after a wide clear. Preserve those as failure shapes to challenge.
