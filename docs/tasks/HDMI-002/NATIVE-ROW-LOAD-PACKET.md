## Operation after commissioning

1. The Olimex operator obtains the slot under the bound operator checkout’s `docs/operations/olimex-bench/README.md`, verifies the actual unit, production application, mainboard companion, EMOS, startup and listener against the job, and records monitor, cable, input, aspect ratio, scaling, capture resolution and frame rate. Preserve `/autoexec.txt`. Start with a responsive Legacy mode-0 prompt and verified empty test destinations. If a destination already contains data, preserve it and choose a fresh namespace before staging. The three namespaces keep save/score state independent. The operator retains firmware readbacks and the SD staging receipts (transport completion and selected carrier).
2. For each arm the operator uses the binding’s `stage`, then `install-p4` when present. Halt on an identity, verification or recovery discrepancy. Select the reviewed route with `EMOS LEGACY --keep-display` or `EMOS EXCOM --keep-display` at the prompt. Confirm EMOS route, keyboard input and actual display. Change to mode 0 only if needed with `VDU 22 0`; allow at least one second after each mode change. Then `CD /test/native-rows-legacy` (or `-full-frame`, `-native`) and `LOAD rowload.bin`. Smith explicitly starts the appliance with `RUN &040000`. Separate preloading, mode settling and execution as in the [test-appliance procedure](../../procedures/test-appliances.md).
3. For a menu command press its letter, type the decimal mode, then Enter. `P`, `C`, `R`, `D` and `B` return to the menu on Escape. `T` starts ten round trips immediately. `Q` returns to a visible, flashing mode-0 CLI. The eZ80 queries the selected VDP through EMOS, changes mode only when necessary, allows 160 MOS ticks for a changed display and reports a failed query or mode mismatch. The preview validates the existing stream’s mode header and emits its remaining bytes unchanged. Read the mode/status from the owning output. In Legacy, P4 HTTP status describes the P4; the mainboard mode query and the VGA output identify the VDP actually driving the picture.
4. Before leaving an arm, the operator obtains its CSVs, raw observations, input/event timestamps, video and readbacks, verifies a responsive visible CLI, restores entry route/mode and working directory and closes passive capture. Run `restore-p4` when present and verify readback. End the job with `handback` under the commissioned procedure. A return to the menu or a loaded executable does not launch the next arm. Preserve the first unexpected failure with its last known mode, status and scene before following the operator stop/recovery procedure. A fail-stop may leave the eZ80 waiting for a swap or queued primitive. Use the independent P4 HTTP and passive serial capture for the fault receipt, then follow the commissioned recovery procedure.

## Capture and scoring

The reserved operator starts the read-only [Pi observer](native-row-load/observe.py) on an identified, idle P4 serial port, using the bound interpreter, from the packet source directory. For example, under the bench’s normal process supervision run `.venv/bin/python <packet-source>/observe.py --binding <packet>/operator-binding.json --arm native --seconds 60 --hz 1 --output <new-window-directory>`. Use `--arm legacy` or `--arm full-frame` for their runs. `--hz 0` samples at the boundaries, `1` is the nominal workload and `4` is the added network load. Set `--seconds` to cover each actual test and its markers, extending for transitions and the soak. For a 60-second stable-scene sample, enter the scene and let the mode settle, start the observer, hold the workload through its closing sample, then press Escape. Keep continuous external video across entry and exit. The observer writes raw passive P4 serial bytes, host timestamped offsets, request start/completion, errors and raw JSON. All arms issue two live GETs per sampling period; in native they read `/display/status` and `/display/scanout`. The other arms query `/display/status` twice. Native also checks `?last_fault=1` at epoch/fault changes and window edges. Record achieved load and distinguish probe-induced timing costs. HTTP timestamps identify when the Pi read data; polling does not time individual interrupts.

1. **Software refill.** Run `python3 <packet-source>/score_refills.py <window>/observations.jsonl` for each steady native window. The [offline scorer](native-row-load/score_refills.py) returns JSON with the measured deltas, histogram intervals, software checks and outstanding physical verdict. Compare endpoints in one active epoch and stable mode. For 684×384 there are 12 blocks/frame, for 848×480 there are 15. Check positive progress of `frames`, `blocks`, `ready` and `draw_wakes`; bracket endpoint partial frames and in-flight slots. For stable mode, `abs(Δblocks − blocks_per_frame × Δframes) < blocks_per_frame`, `abs(Δdraw_wakes − Δframes) ≤ 1` and the absolute difference between `Δblocks` and `Δready` must fit the three-slot ring. An unexplained discontinuity, blocked HTTP, missing interval or silent display needs separate reporting. Save `fault`, `underruns`, `invalid`, `rejected`, failing frame/block and the queue/render/sync partition of that refill. Stop on the first new fault. Compare the saved register’s epoch with the start snapshot; an older retained fault is prior evidence. A new fault after mode entry can be visible only in the saved register. `sampled_rows` gives cycle samples for the native lock, stock composition and expansion. It cannot establish a total count of all rendered source rows. Retain the independent pixel/row-count oracle for exhaustive offline checks.
2. **Service-time tails.** Retain `max_refill_us`, `worst`, `min_sw_lead_us`, `min_draw_gap_us` and queue high-water. `4294967295` denotes an unobserved minimum. Compute 17 histogram deltas within one epoch. Bins 0–15 each represent 100 µs; bin 16 means ≥1,600 µs. Report p99/p99.9 as the enclosing bin and worst in µs. Bound queue backlog across the active burst, verify sustained command/input progress and inspect phase outliers including 8→20 and wide clear. The epoch maximum might have occurred before an isolated window. Subtract additive counters only. Startup, transition and teardown require their own time/epoch evidence; a 4 Hz poll can miss short epochs. An epoch with missing timing data cannot pass the timing gate.
3. **Physical deadline.** Both timings have 1,104 clocks per physical line at 240/7 MHz, giving 32.20 µs/line and **1,030.4 µs per 32 active rows**. The ring has three slots. Two 32-row intervals give approximately 2,060.8 µs before reuse in an uninterrupted active burst, subject to actual descriptor fetch and FIFO lookahead. A measured software refill above 1,600 µs or a driver fault fails the candidate. A passing physical verdict additionally requires a supported witness for actual retirement and earliest subsequent source fetch, or validated conservative bounds on both. Establish a common-clock trace, worst interrupt delivery latency, prefetch bound, probe skew and timestamp uncertainty. Require (hardware retirement → publication including its error bound) ≤1,600 µs **and** (earliest next fetch − publication − uncertainty) >0 for every tested slot including frame wrap. The software `min_sw_lead_us` ends at a callback. A capture card only sees the downstream video. If independent hardware evidence is unavailable, record **physical deadline unverified**, even with a clean picture and zero software faults. Use the offline delayed/refused-handoff tests for negative controls. A hardware-injected fault needs a separately identified diagnostic build and commission.
4. **Motion and sync.** Align the three videos by the game’s visible scene and logged input. Compare useful changed images/second, cross-height displacement and discontinuities per scrolling minute. Record game speed separately from P4 DMA frame completion. A camera shutter or monitor scaler can create bands: compare raw incoming frames and VGA/HDMI processing differences where evidence allows. Record any black interval at its timestamps with monitor/receiver timing lock if independently observable. Mode-transition black intervals, steady-game black pixels and a receiver losing lock are distinct observations. Preserve an incident without expanding this judder test into a link investigation.
5. **Work and memory.** Report `rowload.csv` useful loops/s, SD bytes/s, exposed input events, free internal/PSRAM bytes, largest internal block and `largest_internal_dma_bytes` (largest contiguous DMA-capable internal allocation) at identical mode/scene boundaries. Report lock/stock/expand samples in CPU cycles per sampled source row and separate queue/render/sync µs. Note actual clock for conversions. A sampled phase counter and throughput do not measure total CPU utilization, allocator history, or interrupt count. Report unsupported metrics as unavailable, including idle CPU/primitive p95 without a suitable witness. Show Legacy, full-frame and native side by side. For native vs full-frame use `100 × (native − full-frame) / full-frame`; for stock drawing use Legacy as baseline. Indicate units, workload, actual exposure and ranking criterion, worst first. Keep the minimum physical lead, software margin, observed visual result and unverified items in independent columns. The native status also reports `largest_internal_dma_bytes` with the allocator capabilities used by the slots. A new carrier needs three separate aligned regions of 81,408 bytes at 848 or 65,664 bytes at 684. A previous build ran out of contiguous internal memory on 848→684. Capture the end of the loaded run and both carrier re-entry directions. A stack high-water figure needs a separate witness.

## Obtaining a physical bound on this P4

The pinned IDF 5.5.5 DW-GDMA block callback supplies neither the hardware event timestamp nor a block identity. Pre-v3 DSI supplies the bridge underrun interrupt. The P4 event matrix exposes DMA2D events for a different engine. The candidate can record which invalid linked-list descriptor DW actually requested, a software READY timestamp, and positive channel-stop acknowledgement. Its normal status endpoint cannot timestamp the first bus fetch.

If this hardware witness becomes necessary, seek a separate diagnostic commission. For one frame/block at a time, record its normal post-clean ready point, delay its VALID marker by a measured interval, and record the actual publication time. Keep the normal positive-stop protection. Require a deliberate excessive delay to trip the hardware invalid-LLI event on the chosen descriptor. Completion after a smaller delay supplies a lower bound on first admission relative to normal readiness for that trial. In TRM §7.5.4.2, p. 785, DW discards a speculative fetch that sees INVALID and retries at the previous block’s end. The diagnostic delay can therefore change the natural time of first pixel fetch. Retain a separate conservative bound for unmodified prefetch. Use common-clock timing, leave IRQs enabled, and distinguish a hardware invalid-LLI event from the software deadline or a withheld frame rearm. At the frame seam, include the explicit EOF rearm before treating block 0 as requested. Repeat across each slot and matched loads. Compare with an unmodified run for perturbation. For the other endpoint, a separately isolated diagnostic can bracket one raw DW block-transfer-done transition between a timestamped clear and set observation with a single acknowledgement owner. Bound the sampling gap and probe overhead. Reject ambiguous or coalesced transitions. Without a characterized bracket at both ends, report the physical retirement-to-publication time as unverified. No diagnostic injection or interrupt-mask change is part of this packet's normal candidate runs.

The retained P4 TRM (SHA-256 `622fe9625d19cf00bd7aa49e65f0b5dd6ef2197f83cb7a88b4405078d6a957d4`) also describes a possible direct source-read witness. §§7.7.1, 20.3.2.2 and 20.5 map the VDMA channel to a read permission monitor, with 4 KiB-granular regions and a fault record identifying master, direction and address. A separately reviewed diagnostic could isolate one slot on exclusive pages, arm denial for that VDMA reader after old-slot retirement, preserve normal descriptor publication, then lift denial at a measured offset after READY. First demonstrate on the actual silicon that a deliberately late release reports precisely that slot’s read and that the monitor fails a prohibited request immediately. Positive trials also need bounded, timestamped gate installation/release, a lossless fault record, normal progress and matched probe-off controls. This avoids moving the descriptor-validity edge. Hardware availability, bounds and probe perturbation remain to be demonstrated.
