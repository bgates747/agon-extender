The 220 Ω resistors are series elements: they can damp transitions and limit
current, but do not set idle levels or provide isolation. Their suitability
depends on the actual drivers, wiring and timing. The 15 kΩ resistors bias the
connected Port C signals high when undriven; they do not select UART/parallel
mode or prevent opposing output drivers. At 3.3 V, an ideal low draws about
0.22 mA through each pull-up. These explanations are not measured results.
The discussion used [TI's series-resistor explanation, §3.10.2](https://www.ti.com/lit/an/spma059/spma059.pdf)
and [open-drain explanation](https://www.ti.com/document-viewer/lit/html/sszt544)
for the general component roles, not as Agon/P4-specific qualification.

## Discussion notes — traffic ownership and VBlank

On 2026-09-07 the Author proposed EMOS as the sole driver of traffic in
Exclusive Compatible and asked about exceptions such as VBlank. This is a
question about ownership and event origins, not an accepted requirement for
an exclusively polled or electrically one-way connection.

The accepted architecture gives EMOS sole ownership of eZ80-side routing,
activation, transport reception and canonical MOS state updates. The stock
audit separately establishes unsolicited keyboard/mouse UART packets,
automatic mode-information packets and independent display timing. Responses
and events can originate at the selected VDP/EDP without a separate EMOS
request for each packet; this does not transfer routing authority from EMOS.
See [primary traffic evidence](AUDIT-004/trace-primary-protocol.md).

On the selected stock Light 2 drawing, onboard VDP GPIO15/VSync connects to
eZ80 PB1. Its rising edge invokes MOS's VBlank interrupt handler, which updates
the MOS clock. This is a separate physical signal, not a UART message or the
GPIO17/ITRP route. Selecting the P4 as compatibility display processor does not
by itself change that board wiring. The Exclusive Compatible timing source
and its delivery to EMOS remain Q005, not an instruction to add a wire.
See [VBlank evidence](AUDIT-004/trace-vdp-interfaces.md).

## Discussion notes — periodic interrupt and releasing PB1

The Author clarified that the immediate timing requirement is a 60 Hz interrupt
on the eZ80 side and deferred display-latency compensation unless measurements
show it necessary. Keep this requested rate distinct from the retained stock
mode-dependent frame cadence; the compatibility consequence remains Q006.
The Author asked whether halting onboard VDP could make PB1 available.

The stock audit's [board evidence](AUDIT-004/trace-hardware-and-dependencies.md)
establishes onboard GPIO15 driving the PB1/VGA VSync net and a shared physical
reset net reaching both processors. Holding that reset net low is therefore
not a way to keep the eZ80 running while independently disabling onboard VDP.
VDU 21 stops command processing while leaving display generation running;
it is not an output-release command. The reached
[VGABaseController::end](https://github.com/AgonPlatform/vdp-gl/blob/ac2dd5986daf496c43ae8e7fe41836274aec54a0/src/dispdrivers/vgabasecontroller.cpp#L121-L148)
stops its stream but does not explicitly restore the output GPIOs to inputs.
Stopping a processor/task or video engine alone is not evidence of high impedance.

A custom onboard-VDP firmware path could stop the VGA engine, disconnect its
GPIO15 peripheral output and disable that pin's output driver. Espressif's
[GPIO API documentation](https://docs.espressif.com/projects/esp-idf/en/v4.4.6/esp32/api-reference/peripherals/gpio.html)
describes peripheral disconnection, direction and pull controls. This supports
the feasibility of deliberate release, not a qualified handover. Stock VDP
does not provide an identified command for this complete operation. Reset,
restart and mode-restoration paths would also need to prevent GPIO15 and a
new timing source driving the net simultaneously. No firmware modification or
new connection is authorized by this discussion. An EMOS timer interrupt is
another candidate if the requirement is the periodic service rather than the
physical PB1 source; its compatibility and timing have not been evaluated here.

### Timing discussion disposition

The Author subsequently agreed to retaining the onboard VDP as the 60 Hz
source for the first proof (D003), superseding the proposed P4-to-PB1 handover
for that milestone. Q005 is resolved for this initial proof; Q006 retains the
broader compatibility boundary. The onboard VDP must stay configured for the
selected cadence while EMOS routes ordinary application display commands to
the P4. No firmware implementation or physical operation follows automatically.

The onboard MOS/VDP connection uses eZ80 UART0 on PD0–PD3; the external Port C
pins PC0–PC3 provide UART1. Port C is not the eZ80's only hardware UART port.
The [audited board routes](AUDIT-004/trace-hardware-and-dependencies.md) retain
the exact endpoints. Both UARTs can therefore have separate roles without
sharing Port C signal conductors.
