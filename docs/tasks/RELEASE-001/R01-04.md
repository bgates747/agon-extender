# R01-04 — Clean reconstruction and compression correction

## Executive summary

The maintained P4 build now contains the mapped deployed composition and builds
from a clean Git export into fresh output directories. The separately identified
correction restores browser compression requests without changing credit pacing.
EMOS and the SD MOSlet rebuild **byte-for-byte identical** to their preserved
installed payloads. P4 builds pass local browser/codec checks, but are **drafts,
not deployed or hardware-equivalence qualified**. R01-05 packaging is next.

[Machine-readable results](BUILD-RESULTS.json) retain hashes, source commits,
actual compiler definitions, browser checks and host-input pins. The existing
preservation bundle remains the rollback authority; none of its evidence changed.

exact hashes, as permitted by the version policy. No new EMOS or listener version
was invented. Their source ownership remains in agon-emos and mos-agondev.

P4 identity, compiler/debug paths and reset-profile substitution affect bytes;
the query correction also deliberately changes behavior. These are known input
differences, **not proof that every binary difference is harmless metadata**.
The task requires hardware equivalence validation before promotion. Both clean
builds leave the private reset endpoint unset; their reset button stays disabled
until the operator supplies `--reset-url` when preparing an installation build.
The reset UI/code is retained and the endpoint is recorded in the local manifest.

## Consolidated inputs

R01-03's selected RLE2, palette packing, six-bit packing and pair-RLE sources are
now maintained under `vdp/video/extender/`, with provenance beside each promoted
header. The P4 network service and browser decoder retain the selected wire
formats. Buffered command 65 retains the installed RLE2 extension and unchanged
stock TurboVega fallback. Official Buffered Commands API documentation was
reviewed; no new stock API or upstream defect fix was introduced.

The console target retains the deployed profile's explicit drawing, memory,
snapshot, output-priority and timing flags. It selects the existing hash-guarded
ESP-DSP lifetime derivative through maintained configuration, without requiring
an agent's shell variable. Separate diagnostics/recovery source remains in place;
the ordinary console does not select the newer frame/graphics-timing composition.

The retained effective SDK configuration is now a tracked console input. Both
builds match its SHA-256 exactly. Fresh PlatformIO verbose logs establish that
SCons passes the selected flags to the actual display/network compilations and
compiles the generated DSP derivative. CMake's compile database alone was not
sufficient evidence, as R01-03 warned.

One inherited discrepancy is explicitly retained: final commands contain
`-std=gnu++17` followed by `-std=gnu++2b`, so the latter wins despite the existing
source-selection comment's C++17 intent. This reconstruction does not silently
change the compiler language mode. Any correction needs separate review before
being mixed into equivalence testing.

Pinned tool versions: PlatformIO 6.1.19, pioarduino 55.03.311, Arduino 3.3.11,
ESP-IDF 5.5.5, RISC-V toolchain 14.2.0+20260121. Selected dependency lock and
managed-source hashes are captured by each local manifest. Downloaded tool
packages may be reused; source exports, managed components and compiled outputs
are fresh. This is not a hermetic toolchain distribution or fresh-machine proof.

## Commands and validation

The [build guide](../../building.md) owns the maintained commands. At a clean
checkout, the P4 entry point is:

```sh
.venv/bin/python scripts/prepare_console.py --output agents/release-build
.venv/bin/python tests/browser_bundle_test.py --bundle agents/release-build
```

The control was built from `70a39d4f`; the corrected build from `81686649`.
`--expect raw` is only for testing the preserved control. Default testing requires
compression negotiation and rejects that control, proving this regression is
observable. The test verifies the full five asset byte sequences in the actual
application binary, serves those exact exported assets locally to Chromium,
intercepts the WebSocket constructor, and checks the requested URL. No P4 network
session is opened. The same built decoder roundtrips host-compiled encoder output
through 48 cases spanning 320×240, 512×384 and odd-sized rasters, including raw
fallback, RLE2, palette/six-bit packing and pair-RLE.
