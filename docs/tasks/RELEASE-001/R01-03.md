# R01-03 — Deployed P4 source composition

## Executive summary

The retained reset-button build can be mapped to existing source and tracked
codec research without replaying every historical experiment. Most current code
already matches: 5332 tracked VDP-tree files are identical, 17 differ and nine
are absent from the retained snapshot. All 5117 snapshot vendor files match.
Four extra codec files have exact tracked counterparts. No missing proprietary
source was found within this review; clean reproduction is still unproved.

**A browser behavior discrepancy needs explicit disposition:** the reset build
connects to bare `/video`, losing its parent's `?rle2=1&packed=2` request, and
sends credits without the parent's explicit 60-Hz spacing. Its encoders remain
present but unrequested by the ordinary page. These are confirmed source/binary
facts, not a new performance result or proof of every reported slowdown's cause.

Contract frozen in `b8a80e3d`. No build, source migration, emulator, network or
bench action occurred in R01-03. R01-01's read-only browser captures were reused.
The next implementation is R01-04, not execution of old preparation scripts.

## Evidence strength and counting

[COMPOSITION.json](COMPOSITION.json) records hashes, inspected selections and
file dispositions without private paths. The input snapshot and binaries are
those preserved in [R01-01](R01-01.md). All five browser asset byte sequences

The tracked-file count covers files returned by Git under `vdp/`, not all files

including ignored generated files, diagnostics and recovery outputs. Different
counts reflect those different sets. Neither is an exhaustive upstream semantic
review. Source hashes establish equality, not qualification.

## Build configuration map

Retained build log records PlatformIO 6.1.19, pioarduino 55.03.311,
Arduino-ESP32 3.3.11, ESP-IDF 5.5.5 and RISC-V toolchain 14.2.0+20260121.
Board definition, SDK defaults and partition source match current files.
The console-specific dependency lock matches current selection; the root lock
may reflect another target and must not replace that pinned input.

Retain the effective SDK configuration, managed-component lock and selected
packages from the preservation record. Its `.pio/packages` link targets external
packages; the archive is not a hermetic toolchain. Pin/resolve these dependencies
and capture actual compilation in R01-04 before claiming reproducibility.

The retained PlatformIO profile declares video polling at 1 ms; internal pools,
game/framebuffer allocation; four drawing opportunities; row-pair output;
snapshot mutex/lookahead; below-parser output priority; packed rows; telemetry,
refresh tracing and video timing. It also declares DRAW_TWICE, but DRAW_FOUR has
source precedence when both are effective. These flags affect behavior, not just
build labels. Do not “simplify” them as part of consolidation.

**Compiler-evidence limit:** CMake's compile database contains only the explicit
component definition `AGON_EXTENDER_STOCK_RUNTIME=1` for the inspected display
unit. The retained PlatformIO log and SCons signatures show a separate final
compilation path. Therefore the CMake database alone neither proves all profile
flags reached final objects nor proves they were ignored. R01-04 must capture the
actual compiler invocation and compare it with retained object/ELF behavior.
The map distinguishes declared flags from effective flags rather than guessing.

The selected build also enables the existing hash-guarded
[DSP lifetime derivative](../../../vdp/pio/dsp_matrix_lifetime.cmake).
The compile database selects generated `agon-extender-dsp/mat.cpp`, and the
source recipe is unchanged. Preserve that existing correction and hash guard;
this authorizes no new upstream bug fix. Generated build identity/status and
reset endpoint also affect bytes and need explicit inputs rather than ambient
Git state or private source edits.

## Browser discrepancy and decision boundary

In the preserved key-query parent, `connect()` appends `?rle2=1&packed=2`, and
`sendCredit()` waits until at least 1000/60 ms after its previous send. The reset
build removes both while adding reset handling. The selected P4 handler requires
an explicit query to enable each encoder, so a bare `/video` uses raw frames.
Its ordinary page still returns credits after presentation via requestAnimationFrame;
there is no explicit fixed 60-Hz spacing in that send function.

This contradicts the [accepted compression default](../../decisions/ADR-0021-rle2-browser-default.md).
It does not establish causation or magnitude of historical performance reports.
No live video subscription or timing experiment was run. The separately recorded
30-Hz policy versus 60-Hz experiment question remains with its existing owners.

D01 in the main task owns correction authorization. R01-04 may reconstruct the
exact preserved behavior as a control; it must not silently restore compression,
change request pacing, or call the discrepancy accepted merely because the reset
feature passed review. Promotion requires the discrepancy to be resolved or
explicitly accepted as a limitation by the Author.
