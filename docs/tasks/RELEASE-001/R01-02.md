# R01-02 — Installation bundle and acceptance specification

## Executive summary

Provide one `production/` entry point selecting an immutable, compatible set of
P4 firmware, EMOS, EMOSlets and host tools. Generate its installable archive from
canonical sources; retain binaries outside Git. Reuse the existing artifact,
build and baseline records. Preserve the recorded working installation until a
cleanly built replacement passes the bounded matrix below and the Author accepts
it. No current selection, artifact identity or lifecycle status changes here.

This is the R01-02 specification, frozen for preparation in `a3650e43` after the
prior results were pushed. R01-03–08 implement it under their existing gates.
[Preservation](R01-01.md) supplies evidence, not a ready production release.

## Contents and ownership

| Package part | Required contents / owner | Scope |
|---|---|---|
| P4 | Extender build owner supplies identified app and required bootloader/partition/OTA companions, exact offsets/settings and hashes; embedded browser comes from that same build. | Required. No independently updated browser copy. Full device backup remains private recovery evidence, not a distributable image. |
| EMOS | agon-emos owner supplies resident firmware, exact source/toolchain inputs, size and expected padded ROM hash. | Required. Preserve input, ordinary VDU routing and utility dispatch; do not substitute stock MOS. |
| EMOSlets | agon-emos owner supplies MOSlet-layout `sdserve.bin`, identity, RAM bounds and matching protocol. | Required, installed at `/emos/sdserve.bin`. Ordinary application fallback is optional and must be distinctly named/located. |
| Host clients | Extender owner supplies pinned `sdcard.py`, `keyboard.py`, `screen_text.py` and their actual runtime dependencies from canonical source. | Required client set. Linux/macOS use their own Python, not a copied virtual environment. Native Windows remains unqualified. |
| Reset support | Extender owner supplies reset clients, Pi bridge and configurable service/pulse support. | Optional installation profile; preserve this capability for the existing bench. No private endpoint, sudo policy or device wiring assumed on another host. |
| Onboard VDP | Operator records exact compatible image identity/hash and origin. | Required compatibility dependency; retain installed firmware. Not shipped or flashed by default. Resolve R01-01-L02 before calling it a known release. |
| Documentation | Package builder includes install/verify/rollback instructions, component/build manifests, notices and compatibility limits. | Required, generated from maintained role-named authorities. No task archaeology for normal installation. |
| Development/recovery evidence | Build owner retains source snapshots, ELF/maps, provenance and applicable recovery tools. | Separate support/source archive or retained references. Journals, private backups and complete old bench trees are not runtime package contents. |

## Storage and selection

The planned tracked structure is:

```text
production/README.md                 # one human/agent entry point
production/current.yaml              # selected baseline + bundle-record paths only
production/bundles/<baseline>/        # immutable inventory/install record, no binaries
    bundle.yaml
    SHA256SUMS
    builds/                          # existing build-manifest format

docs/versions/baselines/<baseline>.yaml  # existing authoritative combination/status
```

`<baseline>` is a placeholder, not an allocated artifact identity. The existing
version authority governs its eventual name/revision. The production README links
the selected record and maintained operation/build guides. Do not create a
misleading empty current selection before acceptance; a candidate is explicitly
unselected until R01-08.

`current.yaml` contains relative paths to the selected baseline and bundle record;
it owns no copied status, version list or per-machine state. The baseline owns
component identities, compatibility and qualification scope. Each adjacent build
manifest owns provenance and output hashes. The bundle inventory maps those
outputs and pinned source files to package paths, distinguishes required/optional
parts, and records the final archive checksum. Generated SHA256SUMS covers all
payload files; the outer archive checksum belongs outside the archive. Validators
must reject disagreement, absent required fields or broken references. Do not
invent a second lifecycle registry.

Generated candidate payloads and archives go under ignored
`dist/production/<baseline>/`, with no overwrite of an existing identified bundle.
The build owner retains an additional verified copy before replacing any installed
combination. Retained R01-01 preservation remains untouched. A local bundle is
sufficient for this task's first acceptance: no hosting service or public release
is required. Public binary publication and its destination require a later explicit
Author instruction. Routine users receive the archive plus its checksum, not a
symlink into an agent directory. Local storage details remain ignored.

Packaging copies maintained scripts/assets at the pinned commits; copied files
are generated outputs, never another editable source tree. Include selected
license/notices and corresponding source/build materials required by their terms.
R01-05 checks actual selected components before redistribution; no blanket claim
about licensing or permission is inferred from a repository's existence.

## Status and approval boundary

R01-02-S01 — Keep preserved historical binaries and their recorded draft/
experimental/dirty provenance unchanged. Physical success and Author acceptance
are recorded alongside those facts, not used to relabel old builds silently.

R01-02-S02 — Build the replacement from frozen clean commits. Allocate any new
build/version/registry identities through the existing version policy. A byte
change receives a new build identity even if intended behavior is unchanged.
Reproduction means matching bytes where possible; justified metadata differences
require explicit equivalence evidence and are not called bit-identical.

R01-02-S03 — Select a frozen candidate for the stated validation scope, then
record bounded qualification and Author acceptance before advancing current.
`qualified` means only that declared scope. `released` still means deliberate
publication for normal use; this document neither publishes nor promotes it.
If current policy cannot represent the selected combination honestly, stop for
that concrete policy decision rather than introducing an unofficial status.

R01-02-S04 — No pre-existing fault, browser performance limit, deferred peripheral
or untested electrical state becomes a pass through packaging. Document known
limits against the exact selected build. A newly observed regression stops
promotion; do not hide a fix inside packaging without a bounded disposition.

## Bounded validation matrix

Every row needs an evidence reference and exact component identities. Local
checks precede bench checks. An unavailable required observation remains pending,
not passed by inference. The Author must accept any reduced scope explicitly.
No tests in this matrix have been executed by R01-02.

| ID | Observer / action | Required result / boundary |
|---|---|---|
| V01 | Build owner builds P4, EMOS and MOSlet in fresh output/work directories from recorded clean inputs. | No hidden agent snapshot dependencies; versions/toolchains/configuration and output hashes recorded. Explain byte differences from R01-01. |
| V02 | Package checker verifies inventory, manifests, checksums, required files and source/notice mapping. | Exact cross-component references; no private endpoints/credentials or machine paths in public records. Missing files fail selection. |
| V03 | Agent walks installation/rollback instructions as a new reader; runs relevant offline host tests. | Input bootstrap works without depending on a disabled input path. No automatic flash/reset/SD mutation during validation of help/examples. |
| V04 | Operator verifies installed identities and preserves the actual incoming bench state before candidate replacement. | Resolve fresh-image/SD uncertainty from R01-01-L01 and VDP identity L02; record rollback hashes. No command injection into an unknown application. |
| V05 | Operator observes EMOS boot, SD access and prompt; agent checks P4 startup/readiness. | Candidate identities/readbacks agree. Startup is backed up and restored; an intentional install reboot is distinct from a passing application test. |
| V06 | Human uses P4 USB keyboard; human/agent exercise browser capture and bounded agent input. | Letters, modifiers, Enter, Backspace and releases work; physical takeover and capture release match maintained ownership. Retain fullscreen Escape limitation. |
| V07 | Operator switches Legacy/ExCom and back using EMOS. | Display route and keyboard admission follow current contract; Legacy browser input works without claiming Legacy video mirroring. Mainboard port remains excluded by BC-001. |
| V08 | Browser observer checks text/graphics, reconnect and served assets; agent reads ExCom screen text. | Correct selected frame decoding; no stuck/newly corrupted output. Screen text remains pixel-derived and non-atomic, not Legacy readback. No new FPS target. |
| V09 | Operator starts normal and fast foreground EMOSlet sessions; host client uploads/reads scratch data and exits/reenters. | External readback matches in both tests; both endpoints must opt into fast mode. Fast upload alone still makes no whole-file verification claim. Ordinary application-memory sentinel retained. |
| V10 | Human verifies optional browser reset with the Pi bridge; agent verifies subsequent boot/admission. | One deliberate reset with confirmation, no retry; button placement/silent success preserved. Optional-absent profile leaves control clearly unavailable. |
| V11 | Human compares a bounded familiar game and CLI/UI session against the preserved combination under matching mode/browser conditions. | No new hangs or material regression. Gameplay judgment is recorded separately from FPS; no open-ended benchmark campaign. |
| V12 | Operator verifies final startup, user-file preservation, service/input state and rollback material. | No unexpected foreground listener, pending transfer, held key, serial/video observer or changed startup left behind. Report intentional final state. |

Use maintained [bench constraints](../../qualification/bench-constraints.md),
[SD layout](../../sd-layout.md), [keyboard](../../remote-keyboard.md),
[SD service](../../mainboard-sd.md), [reset](../../bench-reset.md) and
[capture controls](../../qualification/capture-failure-protocol.md). Video mode
selection for fixtures belongs in startup, not inside the fixture. Use only
minimal scratch files in approved locations; no user game installs are replaced.

Linux host checks and Mac browser acceptance are separate observations. If the
Author has only one host available, record the other as untested rather than
promoting cross-platform qualification. R01-06 emulator changes retain the
explicit human validation/commit gate. R01-07 obtains bench availability and
deployment authorization before changing hardware; this matrix is not that grant.
