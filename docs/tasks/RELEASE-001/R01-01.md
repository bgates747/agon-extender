# R01-01 — Working-installation preservation

## Executive summary

The recorded working combination is preserved with hash-checked firmware,
source/build snapshots, host tools and deployment evidence. Read-only live checks
match its browser assets and Pi reset bridge. **This is not a fresh whole-device
identity verification or an approved production bundle.** The SD listener was
offline; neither board was reset, flashed or interrupted to obtain a new readback.
R01-01 closes with these explicit limits. R01-02 is the next review chunk.

The contract was frozen in `f2ca2045`. Exact artifact/archive hashes and bounded
checks are in [PRESERVATION.json](PRESERVATION.json). Private paths, snapshots,
endpoint configuration and receipts are retained in the ignored local preservation
record. No binary, private topology or generated source tree is published here.

## What the preservation contains

The local collection is approximately 600 MB, including compressed source/build
archives. Every regular member of the P4 source and build archives was compared
with its original; the same check covers retained EMOS provenance/builder,
EMOSlet and host-tool archives. Standalone images match their recorded hashes.
Tracked-source archives pin Extender, agon-emos and mos-agondev commits. Parent
transformation entry points are retained for R01-03; their complete semantic
composition has not been reviewed in this step.

Archives preserve symbolic links, not the contents of external toolchain/package
or virtual-environment targets. Those targets remain dependencies to resolve in
R01-03/04. Current tracked EMOS source is preserved in addition to the original
build provenance; it is not declared the complete byte-reproduction recipe merely
because selected source hashes match. No compiler or build was run here.

The P4 factory image is a deployment prefix, not a full 16 MiB flash backup.
Uncovered mutable partitions are not claimed preserved by it. The preserved
EMOS and mainboard VDP readbacks are historical readbacks, not new observations.

## Rollback selection and procedure boundary

R01-01 preserves rollback material, but does not authorize executing old scripts.
Before a later deployment, the operator must confirm bench ownership, current
physical identity and state, and resolve the live-image uncertainty below.

1. **P4:** to return to this recorded combination, select the preserved r02
   factory image by its manifest hash, not the source tree or a new base build.
   The retained receipt writes that factory prefix at offset zero and verifies
   the same range. The image contains the checked bootloader, partition table
   and application; existing deployment tooling still needs a fresh preflight.
   Retain the current device's actual contents before any future replacement.
2. **EMOS:** select the preserved v0.1.19 candidate and expected padded-ROM hash.
   Prepare any reinstall through the maintained MOS installation/recovery path;
   verify complete ROM afterward. Do not run historical one-shot flash scripts
   blindly or replace startup from an old receipt. The older v0.1.18 ROM is
   historical fallback evidence, not an interchangeable `/emos` installation.
3. **Listener:** restore the preserved MOSlet to `/emos/sdserve.bin` only with
   compatible resident dispatch, a stopped/non-self-overwriting installation
   path and verified readback. Retain startup and user files. The ordinary
   application payload is not interchangeable with this image.
4. **Host/Pi:** select preserved host sources and bridge files, retaining local
   endpoint configuration. Restoring files is distinct from running the reset
   actuator; never use reset as an incidental installation check.
5. **Onboard VDP:** leave it unchanged. Its retained bytes provide recovery
   evidence, but the release identity and applicability must be resolved before
   scheduling any replacement.

## Remaining boundaries for subsequent chunks

R01-01-L01 — Live full-image identity remains unverified for P4, EMOS and onboard
VDP, and the installed listener was not freshly downloaded. Network asset equality
supports browser identity only. Before replacement/promotion, arrange an explicitly
bounded live verification with the application/service state preserved or restored.
The offline listener is not a reason to inject commands into an unknown application.

R01-01-L02 — Mainboard VDP release identity is unresolved despite known bytes and
retained restoration evidence. Match the image against available release/build
records before describing it as stock or selecting it for redistribution.

R01-01-L03 — Build snapshots still use external dependencies; archived artifacts
are not yet a clean public rebuild. R01-03/04 own composition/reproduction.

R01-01-L04 — Existing draft/experimental labels and dirty-build provenance remain
unchanged. Author-accepted operation is not silently promoted to formal release;
R01-02 owns the bundle/status boundary.

These are conditions on the already planned chunks, not new implementation
subtasks. No new firmware identity, benchmark, emulator change, SD write or
hardware qualification was created. End-of-step observations: P4 keyboard ready
and neutral; SD listener offline; no agent video client or serial port opened.
