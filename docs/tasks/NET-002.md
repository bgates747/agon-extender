# NET-002 — Agon networking prior art and Extender reuse review

Review PerryZi, Zimodem and the Agon networking tools discussed in the supplied
Discord transcript before choosing further Extender networking features. This is
the Author's top-priority research task. Identify existing code, interfaces and
user workflows we can reuse faithfully, and explain where adaptation is required.
No implementation choice is made by creating this contract.

## State and authority

Created 2026-09-23. Author subsequently authorized an autonomous goal for the
review subtasks. N02-01 through N02-05 are complete as source research; N02-06
awaits Author disposition. No implementation, physical tests or architecture
changes were made. Read the [decision brief and comparison](NET-002/REVIEW.md),
[claim register](NET-002/CLAIMS.md) and [revision manifest](NET-002/SOURCES.json).
Unverified compatibility/performance claims and unresolved provenance are marked
explicitly rather than treated as passing tests.

## Evidence and scope

The [supplied transcript](NET-002/discord-software-2026-09-23-transcript.md) was
read from Discord by a Mac agent. Preserve its text, message links and stated
capture limitations. Attachments are references, not inspected evidence.
Community compatibility and speed reports are claims to examine, not our tests.

Initial source leads:

1. [PerryZi](https://github.com/SanPollo/PerryZi): ESP8266 module targets,
   Espressif AT compatibility, Zimodem ancestry and claimed SLIP/PPP support.
2. Zimodem: resolve the exact upstream and inherited revision from PerryZi's
   provenance rather than selecting an unrelated current tree.
3. [Radiotux Agon-Software](https://github.com/Radiotux/Agon-Software):
   [get](https://github.com/Radiotux/Agon-Software/tree/main/get),
   [zget](https://github.com/Radiotux/Agon-Software/tree/main/zget), ntpsync,
   ping, route, ipconfig, nslookup and arp. Locate the actual Telnet and Snail
   implementations referenced by participants before assessing them.

Review both Agon-side software compatibility and potential P4-side reuse. An
ESP8266 firmware target is not automatically portable to P4 or Ethernet. Sharing
AT command names does not establish complete protocol compatibility.
