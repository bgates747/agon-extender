# TRS-NET upstream-server probe — r01

Experimental source sample, 2026-09-13. This kit exercises Daniel Paul Martin's
actual `TRS-NET.py` server, unchanged, with a synthetic serial peer and a
temporary volume. It checks ping, binding/header return, two sector reads,
reread and echo, comparing every reply byte with known expectations.

## Try it

Use Python 3.10+ on a development computer. No pyserial installation, serial
adapter, Agon, P4 or bootable OS image is needed. The included probe supplies a
simulated `serial` module; it does not open a real port or network connection.

1. Obtain `TRS-NET.zip` from [Daniel's downloads page](https://danielpaulmartin.com/home/my-downloads/).
   The version studied here came from
   [this archive URL](https://danielpaulmartin.com/sitepad-data/uploads/TRS-NET.zip).
   Keep the archive intact; do not extract or run its server manually for this test.
2. Extract this probe kit and change into its directory.
3. Run the following, replacing the archive path with your own:

```sh
python3 -m venv .venv
.venv/bin/python trs_net_probe.py --archive /path/to/TRS-NET.zip
```

Expect the upstream attribution/notice followed by JSON with `status: pass`,
six successful operations and `volume_unchanged: true`. The temporary volume
contains only generated byte patterns, is not bootable and is removed on exit.
No bundled upstream OS image is opened or extracted.

The probe first verifies the complete archive and script SHA-256. A different
download is rejected before executing its code. If upstream replaces the ZIP,
compare that revision separately instead of bypassing the check. The pinned
archive is 1,770,983 bytes, SHA-256
`52d8f5f0683f6a409c01484283722f4be4296fcd075a6033f29f0e1c727b6f48`.
The contained `TRS-NET.py` SHA-256 is
`f45b34e0b9899b06d04ed67c045ccc9d624c8a5a4f60c5ef712ce555a8d1665b`.

## What this tells us

The inspected server treats its volume as a 256-byte header followed by
256-byte sectors. Its read replies append the byte-sum modulo 256 in a
four-byte big-endian integer. The probe uses the server's existing ASCII
commands; it does not translate Extender's separate SD file protocol.

This establishes a small host-side baseline for a future relay/server
comparison. It does not run the eZ80 driver, measure UART timing, model RTS/CTS
electrically, test partial serial reads or qualify writes, durability, guest
boot or P4 integration. All input bytes are immediately available to the
simulated serial module. The upstream infinite service loop is stopped when
the scripted input is consumed; upstream console-clearing calls are suppressed.
