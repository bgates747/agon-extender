with particular emphasis on HDMI animation and audio. This is standalone

## Implementation decisions and gotchas

1. Reuse Olimex's HDMI BSP at 1280x720, RGB888, and 360 MHz CPU/200 MHz PSRAM.
   Board Rev C and silicon v1.3 are distinct identities.
2. Do not initialize or poll BOOT GPIO35: Olimex shares it with RMII TXD1.
   The Pi sends demo controls through USB Serial/JTAG; the P4 keeps Ethernet active.
3. Audio is generated on command, starts silent, uses bounded duration and
   conservative volume. The P4 outputs through the analog headset jack.
4. Only SD mounting/listing is admitted; do not invoke the upstream destructive
   test or format-on-failure paths. Keep files in place.
5. Preserve upstream driver provenance. Experimental firmware does not alter
   EMOS ownership or provide an Agon transport bypass; no Agon link is present.

## Initial candidate correction

The first native IDF 5.5.5 candidate initialized HDMI and mounted SD but the
`sys_evt` task overflowed its inherited 2304-byte stack while logging Ethernet
startup. Address decoding locates `_vfprintf_r`/`__sbprintf`; retained evidence
is in the local failed-candidate bundle. The project configuration now reserves
8192 bytes for the event task and routes stdout through the installed USB driver
instead of mixing driver RX with direct FIFO output. The stack override is
explicit beside the preparation code; reduce only after measured headroom.
This is an observed integration failure, not evidence of faulty board hardware.

The r02 longer check exposed LVGL/CPU0 starvation while animation timers and
software rendering remained overdue. Retained watchdog traces identify the
LVGL handler and RGB888 software drawing. r03 moves animation updates to a
separate task that takes the LVGL lock and sleeps after each update; the port
can finish rendering and release its lock between updates. Watchdog remains on.
Separately, pyserial open-time modem-line updates reset this USB device; the
Linux command helper uses raw termios without DTR/RTS ioctls, disables HUPCL,
and requires the command echo plus completion prompt (not just a boot prompt).

## Renderer follow-up — r07 and r08 preparation

1. r07 was built, independently flash-verified and booted. Widgets preparation
   returned `ERR widgets memory unavailable` without replacing bars or hanging;
   USB info showed 55,484 bytes free in the original pool. Source inspection
   shows pinned LVGL TLSF derives its maximum pool size from `LV_MEM_SIZE` at
   compile time. A runtime 1 MiB pool cannot be added to the inherited 64 KiB
   allocator. This bounded rejection is informative and retained.
2. r08 sizes the builtin allocator at 1 MiB and uses `LV_MEM_POOL_ALLOC=malloc`
   for dynamic allocation. Fixed IDF PSRAM malloc policy routes that large
   allocation to external RAM; a 1 MiB internal static array would be unsuitable.
   Allocator usage remains measurable; assertions and watchdog remain enabled.
3. Rendering experiment: two panel-owned RGB888 framebuffers, direct dirty-area
   rendering and the port's existing frame-completion semaphore. Replace the
   small single partial buffer/copy path, disable software rotation and change
   both animation scheduling and LVGL refresh to 16 ms. Orbit phase now follows
   elapsed time rather than update count. Pixel/lane/bridge timing is unchanged.
4. Counters distinguish animation updates, LVGL render passes/time and panel
   frame completions. A scanout completion can repeat unchanged pixels; render
   passes and update counts are not independently measured unique HDMI frames.
   Measure comparable elapsed windows and retain Author smoothness review.
5. This is performance diagnosis within the standalone demo, not adoption of
   an Agon rendering contract. The 1280×720 24-circle workload remains fixed
   for comparison with r06; do not imply equivalence to stock Agon at 512×384.
