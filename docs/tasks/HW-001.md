## Intent

Design one production-intent transport circuit for the Agon Light 2 and
Extender V1. The same physical `TX`, `RX`, `RTS`, and `CTS` circuit shall serve
both Exclusive Compatible and Exclusive Extended modes. The circuit shall also
carry Exclusive Extended's one-way eight-bit Agon-to-Extender parallel path,
including its clock, validity, and admission signals. Mode-specific firmware
may use shared signals differently, but V1 must not require two unrelated UART
circuits for the two exclusive modes or a reverse parallel bus.

The currently assembled predecessor circuit and the proposed dedicated
GPIO16-to-PC1 return path are provisional expedients for learning with the
already-wired prototype. They may support bounded PORT-008 experiments but are
not the selected V1 UART architecture and must not be promoted merely because
they work.

Exclusive Compatible uses the common UART circuit for its stock-compatible
command and response transport. Exclusive Extended retains the eight-bit
parallel forward transport and uses the same common UART circuit for its
selected return, control, and fallback behavior. PORT-008 must freeze the exact
mode-specific firmware use before this task freezes the electrical design.

The Author explicitly directed HW-001 on 2026-08-28 to design the complete
UART-plus-forward-parallel circuit and to derive it first from Agon-specific
evidence, then primary component-vendor idioms, with general design principles
used only as a last resort. The resulting topology is explained in
`v1-uart-parallel-circuit-proposal.md`; on 2026-08-29 the Author froze its
placement-independent connectivity as `light2-harness-r02`. The proposal and
generated drawings explain and project that authority but do not replace it.

## Physical endpoint premise

The Agon Light 2 exposes eZ80 UART1 on four immutable alternate-function pins:

| Signal | eZ80 pin role | Agon header pin |
|---|---|---:|
| UART1 transmit | `PC0 / TXD1` | 17 |
| UART1 receive | `PC1 / RXD1` | 18 |
| UART1 request-to-send | `PC2 / RTS1` | 19 |
| UART1 clear-to-send | `PC3 / CTS1` | 20 |

This table identifies the eZ80 endpoint only. P4 GPIO assignments, UART
peripheral selection, buffering, isolation, enable ownership, and mode-specific
signal use remain design work.

## Connectivity representation finding

### Electrical model

Represent connectivity as **nets containing component terminals**, not as an
ordered narrative of wire segments. A net is a hyperedge: every terminal named
as a member is electrically common.

A series component separates nets. For example, `R1.1` may belong to
`uart-tx-source` while `R1.2` belongs to `uart-tx-protected`; the resistor is
the component relating those two nets. A record saying that one wire proceeds
"through pin 3" would incorrectly collapse the component and conductor unless
pin 3 is genuinely one common electrical node.

Every component terminal receives the stable pin number used by its symbol and
footprint. Nonpolar parts still use stable terminal numbers such as `R1.1` and
`R1.2`; the schema may declare them electrically interchangeable without
renaming them between revisions. Polarized parts additionally record terminal
roles such as `positive`/`negative`, `anode`/`cathode`, or device-specific pin
names. Connector and IC terminals record both pin number and immutable pin
name where available.

Physical wire segments, colors, breadboard holes, cable conductors, and test
probes belong in a separate assembly mapping that resolves onto the same
terminal and net IDs. They are not needed to state the circuit's electrical
connectivity.

### Available formats

1. Native KiCad `.kicad_sch` is KiCad's complete editable schematic authority.
   It includes symbols, pins, wires, labels, UUIDs, and mandatory spatial
   coordinates, so it is not the desired placement-free source format.
2. KiCad can export `kicadsexpr` and `kicadxml` netlists containing component
   instances and net memberships. These closely match the desired graph and
   can be compared mechanically, but they are derived netlists rather than a
   portable source from which KiCad reconstructs a well-laid-out schematic.
3. SPICE netlists are compact and connectivity-oriented, but they are lossy for
   connectors, logic-interface intent, footprints, power domains, test points,
   ownership, and many non-simulation properties. They are a possible derived
   simulation view, not a suitable project authority.
4. EDIF can represent netlists and schematics as a formal interchange format,
   but current KiCad does not list EDIF among its supported schematic imports.
   Selecting it would add translation complexity without improving the local
   workflow.
5. SKiDL is a maintained Python circuit-description library that can generate
   KiCad netlists and schematics. It supplies useful implementation machinery
   and ERC concepts, but Python code is less reviewable as declarative project
   data and SKiDL is not an interchange standard.

### Accepted placement-independent authority

The Author approved a project-owned YAML connectivity document validated by
JSON Schema. Model
it closely on the KiCad netlist concepts of components, pins, and nets while
adding the project metadata KiCad netlists omit: terminal roles, polarity,
electrical class, power domain, driver/receiver ownership, provenance,
qualification state, and assembly aliases.

Generate compact Markdown and graph views from that authority. Maintain an
editable KiCad schematic as the human electrical drawing, export its
`kicadxml` netlist with the installed `kicad-cli`, and compare the normalized
export against the YAML authority. A mismatch fails validation. This permits
careful manual schematic layout without allowing GUI edits to silently change
the accepted circuit.

The completed spike generates a deterministic, editable KiCad 7 schematic and
proves exact named-net and intentional-no-connect agreement by exporting and
comparing `kicadxml`. It also found that SKiDL 2.3.0 requires explicit labeled
stubs for reliable layout and a bounded compatibility rewrite because its
`kicad7` writer emits KiCad-8-era syntax rejected by KiCad 7.0.11. This is
useful bootstrap evidence but argues against making generated SKiDL placement
the production drawing workflow. A human-laid-out native `.kicad_sch`, checked
against the YAML authority by the proven comparator, remains the recommendation
pending Author approval.

The accepted task-local schema, semantic validator, electrical-model rules,
and deliberately non-product example live under `HW-001/electrical-model/`.
They define components, stable terminals, nets, intentional no-connects,
polarity/interchangeability metadata, complete terminal accounting, and
canonical ordering without encoding any V1 circuit topology.
