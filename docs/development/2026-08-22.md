## PORT-003 Phase C — Logical frame service planning

Froze the detailed Phase C checklist before production changes and generated
33 exact lifecycle provenance records across 13 pinned official files. The
trace proved that upstream queue-depth waiting can return while a dequeued
primitive is still executing, while old frame edges increment the compatibility
counter before waking bounded work and swaps change visibility before notifying
their submitter.

Added a written-contract oracle with 12 deterministic event traces covering
coalescing, frame-counter writes and rollover, completion races, FIFO budgets,
single/double buffering, bounded slow consumers, disconnect/reconnect, and
teardown payload release. Ten provenance/fixture tests pass and both generated
artifacts reproduce byte-identically.

The Author accepted `PORT-003-D008`: minimally patch the vendored vdp-gl common
controller with default-no-op queued/started/completed hooks and a virtual
completion wait, then keep the P4 sequence policy in project-owned code. This
avoids brittle linker/queue interception and wholesale common-source copying
while preserving stock behavior for non-P4 controllers.

Implemented Phase C's platform-neutral logical frame service and narrow P4
`esp_timer`/FreeRTOS adapter. The service accounts for elapsed ticks, coalesces
stale work, advances the writable 32-bit compatibility counter, publishes an
independent 64-bit generation, executes bounded retained Canvas work, swaps
logical planes, and completes submissions only after publication. The sole P4
owner task is joined before queued work and copied dynamic payloads are
cancelled.

The retained queue integration exposed two inherited ordering races. Upstream
queue-depth waiting cannot see a dequeued primitive, and disabling background
execution can leave a final queued `Refresh` because the private flag changes
after `processPrimitives()`. The accepted two-file D008 patch now distinguishes
reservation, successful enqueue, start, completion, cancellation, and deferred
swap notification; project code drains the trailing refresh and documents the
upstream removal condition inline. The canonical dependency model now treats
vdp-gl as `vendored-patched` and rejects every undeclared changed path.

A pre-candidate audit also rejected the initial consumer callback interface:
calling nominally non-blocking sink code from the frame-service task could let
a slow consumer redefine logical time. It was replaced with eight fixed
latest-notice mailboxes. The producer tries each mailbox lock once and records
a drop instead of waiting; sinks poll from their own tasks and receive no
mutable framebuffer pointer.

All 12 independent traces, five retained-controller cases, three adversarial
stress cases, ten Phase C provenance/oracle tests, thirteen dependency-tool
tests, and the Phase B regression suite pass. The corrected clean P4 build
selects nine application translation units, links all eight required symbols,
contains zero excluded classic physical families, and produces a 597,744-byte
application image. This remains compile/link evidence pending the committed
physical run.

The Author approved `port-003-frame-service-canary-r01`,
`p4-frame-service-qualification-r01`, and artifact registry `r06` for the
