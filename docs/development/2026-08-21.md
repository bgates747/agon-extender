The Author defined **legacy mode** as a third operating mode in which Extender
is electrically and logically absent from the Agon interface even while
connected and powered. Extender v1 explicitly omits printer/USB serial,
console/terminal, ZDI, Intel HEX, YMODEM, updater, and local-debug facilities.
Legacy mode leaves them to the onboard VDP; cooperative mode may still reach
them through ordinary VDU; EDP-exclusive mode must handle attempts safely.
Added SETUP-005-D006 for exact command-level failure and recovery semantics.

The Author accepted deferral of those exact semantics to SETUP-005-D006 and
specified stock VDP behavior as the reference. Unsupported maintenance command
streams should consume and recover like stock as closely as practical. Observed
stock outcomes range from silent failure and harmless garbage output through
hardware reset and ESP32 Guru Meditation.

The Author clarified that improved error handling is an Extender objective but
cannot silently weaken a strict compatibility contract. Strict compatibility
modes permit stock-observable failures, however barbaric; non-strict modes
should replace them with deterministic recovery and diagnostics. SETUP-005-D006
must define that mode-specific boundary before specifying per-command behavior.
