# Development log — 2026-08-27

## PORT-003 Phase F direction

The Author selected Ethernet/browser presentation as Extender's only video
output for the foreseeable future. PORT-003 Phase F will therefore turn the
logical framebuffer into the primary browser-visible product path rather than
treating it as a diagnostic or secondary sink.

The visual reference is the most recent legacy presentation interface at
`agon-extender-legacy@f33b9dd:web/presentation/`: a dark centered shell,
pixel-sharp 4:3 canvas, compact connection controls, and frame-statistics grid.
The selection applies to look and feel. Legacy physical-scanout terminology,
frame transport, buffering, WebGL implementation, and server code remain
evidence to review against the current retained VDP and bounded logical-frame
architecture; they are not imported as current authority.

No firmware or browser implementation began at this point.

The Author then selected direct P4 ownership of the web endpoint. EDP firmware
will serve the browser assets and video endpoint over the DevKit's onboard
Ethernet. The Pi and other bench hosts may deploy and observe the build but are
not runtime relays or product dependencies.

The Author accepted the first browser-video ownership split. PORT-006 owns the
P4 Ethernet and generic HTTP/connection/backpressure substrate. PORT-003 owns
framebuffer handoff, video representation, browser assets and presentation,
and video diagnostics. The narrow supporting PORT-006 tranche does not absorb
OTA, optional Wi-Fi, management, or unrelated network services.

The Author accepted the initial browser-video delivery direction: dynamic-size
uncompressed RGB888 full frames over a client-driven bounded WebSocket flow,
derived from the legacy versioned `EVF1` header. The new implementation will
not retain the legacy server's fixed 320-by-240 or one-frame-only limitations.
The P4 produces final presentation pixels, while slow or disconnected browsers
drop or resynchronize without blocking logical VDP progress. Compression,
partial updates, codecs, and production-rate tuning are deferred until measured
evidence exists.

The first wired-network bootstrap will use DHCP. The existing router
reservation for the DevKit MAC should return the stable bench address; no
address is compiled into firmware. EDP/P4 USB serial diagnostics will report
link and lease state. Friendly discovery and persistent network configuration
are deferred beyond the first forward test.

The Author accepted the first visible-command fixture. It will use official VDP
bytes to select and clear a bitmap mode; draw colored, positioned text; draw
lines and a filled rectangle; and alter and visibly use a palette entry. Exact
bytes and expected pixels will be frozen from official documentation before
bench execution. This representative fixture does not qualify unexercised
commands.

The Author accepted the complete first-fixture actor path. An ordinary eZ80
application uses standard MOS/VDU calls; a fixed-purpose EMOS build owns the
routing and parallel transmission of unchanged official bytes; EDP admits
those bytes to the retained parser and browser-backed display. Application code
does not touch transport GPIO. This is a fixed-route vertical slice, not proof
of runtime operating-mode transitions.

The Author selected explicit first-run activation through the existing EMOS
mode-command framework. Agon boots in Legacy; EDP independently reaches DHCP
and browser readiness; the operator confirms that state and requests Exclusive
Extended. A qualification-only EMOS adapter then prepares and commits the
forward route. It may not auto-enable at boot, and with reverse UART disabled
it cannot claim the eventual EDP handshake or a fully qualified transition.

Planning then closed around one bounded critical path. The proposed PORT-003
Phase F freezes a three-slot immutable RGB888 snapshot pool sized through the
largest retained 1024-by-768 mode, dynamic-size `EVF1`, one-client browser
credit, the accepted legacy visual treatment, a bootable retained-parser build,
and deterministic host/P4 gates. A narrow PORT-006 tranche supplies only DHCP,
onboard Ethernet, embedded HTTP assets, opaque WebSocket sends, and lifecycle
diagnostics. Once Gate F is reviewed, PORT-008 supplies the current parallel
`Stream` ingress and runs the explicit-EMOS visible-command fixture. No code,
deployment, or bench operation was authorized by this planning pass.

The Author approved the complete plan. Phase F contracts and the narrow
PORT-006 browser-video tranche are now implementation authority. Physical
deployment, EMOS changes, Agon connection, and bench execution remain behind
their explicit later gates.
