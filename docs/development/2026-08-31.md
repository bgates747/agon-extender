## PORT-008 first forward-run failure

The Author confirmed the complete r01 harness and LA-03 probe attachment and
cold-booted the Agon for run `PORT-008-2026-09-01-01-29-06Z`. The first
autoexec command, `EMOS MODE EXTENDED`, failed with MOS `Internal error`; the
visible fixture did not execute. The failed run, raw analyzer capture,
deterministic forward-only analysis, sanitized P4 diagnostics, and exact
artifact identities are preserved under `tests/runs/`.

Linked-image inspection proved the primary EMOS defect. ADL-mode
`LD (_port008_length), BC` stores three bytes, but `_port008_length` reserved
only two; the third byte overwrote `_port008_idle_low`. The corrupted release
state kept the P4 transaction from completing until EMOS returned timeout 2,
which the command path exposed as FatFS `FR_INT_ERR` and MOS printed as
`Internal error`. Fab exercised no physical GPIO path, and the linked checks
verified instruction ordering without checking BSS span width.

The same capture recorded a forbidden 135.8015 ms simultaneous assertion of
`FWD_OE_N` and `REV_OE_N`. Independently, the P4 forward candidate does not
configure their assigned GPIO15/GPIO21 controls. Cause remains unresolved and
must be reconciled before another run. Opening USB Serial/JTAG after HTTP
preflight also restarted the P4; future execution must hold the observer from
a deliberate P4 startup through readiness rather than attaching it late. No
firmware correction or retry was performed pending Author review.

## PORT-008 experimental corrections and second forward failure

The Author authorized visibly unversioned corrective hardware-review images.

symbol-span regression. The P4 took explicit GPIO15/GPIO21 ownership, released
both active-low direction controls before output configuration, and selected

passed. The P4 flash independently verified and its controlled startup reported
revision 1.3, QIO/80 MHz, 16 MiB flash, 360 MHz, corrected direction state,

first corrective EMOS image through the one-shot keyboardless process.

Run `PORT-008-2026-09-01-02-10-50Z` nevertheless stopped at
`EMOS MODE EXTENDED` with the same visible MOS `Internal error`. The electrical
result had advanced: the analyzer sampled three falling clock edges during the
first short `VALID_N` window, proving that the corrected length state reached
the physical byte loop. `READY_N` did not release, and the visible fixture was
not reached. The first run's long direction overlap did not recur; one isolated
125 ns reverse-enable sample remains recorded as a failed observation.

Comparison with the hardware-qualified legacy PRX-06 sender found that EMOS had
collapsed each clock-high phase into adjacent Port D high/low writes. The
legacy loop asserts `VALID_N` with clock high before loading data, changes data
while high, then emits a falling and rising clock phase. The old linked check
enforced only data-before-two-control-writes and missed that distinction. EMOS
now mirrors the proven cadence, and both source and linked regressions require
the pre-loop assertion plus per-byte falling/rising phases. The full build and
all 55 repository tests pass; unversioned image SHA-256 is
`8f659845c24a9b328f6791a7ac75a2b820df254bc601517d1b2741ed7999987b`.
It remains pending installation and physical review.
